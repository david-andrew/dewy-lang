- Paper review of the proposal, questions, all 18 programs, and relevant LANGUAGE/v5 rules. Initial grades were formed before opening review-r8. No dogfood files were read. No compiler or timing claims.
- Verdict: promising, but provenance is not yet sound and complete as specified. The common receiver spelling works. Remaining gaps concern identity transfer, facts, control alternatives, and bounded analysis.

- **Provenance and checker findings**
- Separate receiver identity, prepared-operation identity, and registration slot. A named wait needs both its operation key and its original receiver key. Calling it “its own key” conflicts with preserving its key through locals unless both relations are defined.
- Example: `let w = @heart.next; let copy = @w`. State whether `(@w).Tick`, `(@copy).Tick`, and `heart.Tick` all match `select(@copy)`. Recommend preserving the operation identity on copies. Preparing `@other.next` through `other = heart` creates a distinct binding provenance, despite sharing a channel.
- Define duplicate registrations. Registering one copied wait twice must not duplicate consumption or rendezvous with itself. Receiver grouping cannot supply this safety. Retain v5's shared commit token and redundancy diagnostic.
- Define result assignment as well as initialization. `let b = got` preserves provenance, but what about `b = got`, conditional assignment, and two branches carrying the same result? “A join of two results” needs an exact boundary. Recommend preserving identical descriptors and erasing incompatible joins explicitly.
- Captures are missing. LANGUAGE copies implicit captures and permits explicit shared captures. State whether capturing an intact result preserves or erases it. State how a captured receiver's new binding relates to the captured wait. Shared captures and calls with place effects must invalidate affected path versions.
- Receiver path invalidation covers direct ancestor stores. It must also cover writes through `@child`, callbacks, and shared captures using existing effect summaries. Copies of records are independent; do not invalidate an unrelated copied record merely because channel handles alias.
- Generic preservation is circular: “which does not erase it” is no contract. Specify whether a wait returned by a generic identity helper preserves its hidden descriptor. Distinguish passing waits from passing results, which explicitly erases. State how formal receiver keys substitute back into caller keys, including recursion and indirect calls.
- Re-preparing in a loop needs a finite abstraction. `loop box in boxes @box.receive` creates arbitrarily many dynamic waits through one syntactic binding. Define per-iteration identities, saved old waits, and grouping without unrolling the loop into infinitely many compiler keys.
- Nested `merged`/`select` now promises inner provenance. Define whether both `commands.Closed` and `inbox.Closed` match the same close. Include nested merges sharing one inner wait, and inner versus outer idle timeouts. A composed descriptor must retain origin and wrapper relations without flattening away either.
- Direct receive/next/reserve qualification is now explicit and useful. `(@web).string` follows the documented function-handle grammar. `heart.<Tick>` resolves type identity and avoids generic alpha-renaming. Neither rule fills the transfer gaps above.
- Program 10 disproves the stated fact rule. `reserve` is prepared before any nonempty test. The later optional-slot expression reads `local.length`. Attach enabling facts to that registration, not permanently to the reusable wait key.
- Counterexample: enable a reserve while the array is nonempty, clear the array, then select that saved wait. The permit must not prove `pop(0)` safe. Preserve place versions and invalidate the fact after relevant mutation, calls, or shared access. Re-establish it on each loop iteration.
- Payload/control separation needs matching and erasure rules. For `Channel<Canceled>` and `Channel<Closed>`, define what direct receive, qualified patterns, plain family patterns, and `or_throw<Canceled | Closed>` consume. A hidden control tag alone does not define those operations.
- Also define `events.<Event>` when Event contains a control-family type. The current “every alternative whose type is a member” rule can include transport alternatives, while the example promises payload only. Specify role plus resolved type. Preserve that role when source provenance is erased, or reject an erasure that cannot represent it.
- The spin rule is insufficient. A closed source can remain enabled while its arm toggles a flag read only by another wait. This satisfies the written rule and spins forever. Require disabling that ready source, leaving the loop, or a proven blocking/progress step. A mere variable update proves no progress.
- “Earlier argument wins” applies to simultaneously ready candidates. A prepared `@load(url)` is not already completed work. Define the readiness probe and startup order for races mixing reservable receives and ordinary functions. Preserve losing-receive safety without claiming deterministic scheduling.
- Demand-driven descriptors and indexed exact arms are good. The flat bound is credible. It does not bound path-version flow, helper summaries, loop fixed points, or nested source-set construction. Demand provenance tracking from qualified uses and required protocol obligations.
- State bounds in terms of reached descriptors, flow edges, and represented source memberships. Use a shared descriptor DAG or charge repeated memberships explicitly. Bound fixed-point iterations or use conservative erasure/rejection. Keep general coverage cost separate. Flagship instruction measurements remain a landing gate, not evidence supplied here.

- **Clash rule**
- Strong case for existing-member-wins: an established library exposes `heart.Tick` as a counter. Adding selectable outcomes must not break ordinary reads of that counter. An error on every member use would reserve common names retroactively.
- Strong case for an error: a library adds a member whose pattern meaning is plain Tick. A previously source-specific arm can then consume sweep ticks too. A trailing wildcard still handles commands or closure, so coverage need not report an unreachable arm. A missed warning changes behavior after an upgrade.
- Prefer the middle rule. Ordinary member lookup keeps the existing member. Warn at the relevant declaration or protocol instantiation. Error when source-pattern lookup has both meanings; offer `heart.<Tick>`. Do not ban an ordinary field read.
- An error only when history proves an arm changed meaning needs old dependency metadata. A clean build cannot know that history. Use the same contextual ambiguity rule on clean builds and upgrades. This preserves the owner's ordinary lookup preference while protecting source arms.

- **Validity and coverage details**
- 04: `worker.send(back.value) or_throw` can forward `Unsent<Job>`, absent from main's result. No supplied rule specializes this signature merely because this particular channel has no closing peer.
- 10: conditional branches are ordinary expressions. Bare `reserve`/`incoming` invoke zero-argument function-valued locals under LANGUAGE. Argument-list handle exceptions do not apply there. The resulting permit/Job values are not selectable waits.
- 10: its drop hook increments `released` in parallel work. LANGUAGE requires synchronized shared mutable state. The single-threaded counter in 04 has no corresponding concurrency defect.
- 06: `forward<string,string>` can return `Unsent<string>`. Main declares `Unsent<int64 | string>`. Generic covariance/conversion is not supplied here. State it, or declare `Unsent<string>` explicitly. Do not assume Channel covariance.
- 17a: merged's loop item is `string | FetchError`, not `Closed<string | FetchError>`. The close arm is outside the outcome set. The corrected fetch annotation and close-retirement comment fix the earlier errors.
- 05: write bare `read_line or_throw<Canceled>` for the value-producing zero-argument declaration. Its constant Interrupted result is a stub. It does not exercise console interception. Successful-void watch/show/check_cancel/close/stop calls correctly retain `()`.
- 03: the comment selects warning-only clashes while the proposal leaves that choice open. More seriously, unconditional earlier-ready-argument wins cannot also promise v5's no-starvation fair selection. Distinguish the selected priority policy from function-completion ties explicitly.
- 15b: the prepared load partials are not completed results. The closed empty channel cannot produce a string in this setup. Such signature-valid but dynamically unexercised arms differ from 17a's impossible loop-item arm.
- 01's last-close/open rule and 09's drained-versus-idle check now agree with the text. 13 any_close is exhaustive after forwarding both Closed and Canceled. Other match shapes are exhaustive under their intended descriptors; this does not validate unresolved control-payload instantiations.
- Empty arrays and all-none packs need contracts. `collect(workers)` accepts an arbitrary array, but the proposal says at least one wait. Specify immediate empty drain for merged, or require a nonempty input. Specify a static obligation or defined dynamic failure for an empty select.
- Formatting uses ordinary interpolation only. No foreign precision syntax or environment-variable access appears. If formatting is added, use fmt. No program was compiled because these are design samples.
