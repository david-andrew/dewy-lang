# Concurrency stage 4: primitives proposal

Status: complete proposal for David's review. Scope: SPSC, MPMC, Sequencer, SeqLock, Snapshot, and operation-based `select`; design consistency, effects, certificates, verification, and benchmark contract. This proposes surface and semantics only. No repository files are owned or changed. Budget: 5 hours; target: at most 300 lines and a numbered pending-questions list.

## Existing constraints

- Preserve the adopted two-lane model, bounded channels, level-triggered `Canceled`, `Closed` values, `Send`/`Sync` as type facts, scoped place guards, `& no blocks`, and `$no_deadlocks` certificates.
- New surface choices below require David's decision. A provisional library spelling can change before release; semantic guarantees become expensive to revise once programs depend on them.

## Common contract and vocabulary

Recommendations here are proposed signatures, not claims that the compiler accepts them today. `try_*` means one logical attempt without parking or waiting for a peer; an implementation may retry a CAS after interference. `Full` and `Empty` are new, distinct result values, never `none` (a `T` may itself contain `none`). A successful queue send transfers one owned `T`; a failed send must return that `T` to the caller as `Unsent<T>` with `reason: Full | Closed | Canceled`. `Unsent<T>` is an exception value so `or_throw` can propagate it, but its `value` stays accessible when matched. Alternative: make each failure a generic `Full<T>`/`Closed<T>`/`Canceled<T>`; this multiplies spellings and obscures the existing `Closed`/`Canceled` kinds. **Unblocks:** move-only messages and precise failure handling. **Reversibility:** spelling yes before release; no-loss-on-failure semantics no. Existing `Channel<T>.send` is unchanged; this is an expert queue API and should inform a later channel review, not silently change it.

`Closed` means the producer side has closed: accepted items drain in FIFO order, then reads return `Closed`; sends after closure return an `Unsent` whose reason is `Closed`. `Canceled` means the current scope is canceled: any operation designated a cancellation point returns it even if ready, before a queue commit. A successful `try_*` is not a cancellation point and must never implicitly observe or clear cancellation. A close is idempotent, wakes blocking waiters, and does not discard published values. Dropping the SPSC sender or the last Sequencer publisher closes; dropping the SPSC receiver makes sends fail `Closed`. A combined, copyable `Mpmc<T>` handle has no producer/consumer role count, so it requires explicit `.close()` while other handles remain; final handle drop reclaims storage. Alternative: make all closure explicit, risking stranded endpoint waiters. **Unblocks:** structured shutdown without inventing roles for MPMC. **Reversibility:** hard once programs rely on drop behavior.

`& no blocks` excludes parking, syscalls and waits whose completion requires another task. It alone does **not** promise bounded execution time, no contention retries, no allocation, or no `panics`; the hot-path contract must also state `& no allocates & no panics` and avoid unbounded retry in source. `try_*`/single-attempt `SeqLock.try_read` may satisfy `no blocks` only with a reviewed nonparking implementation. `send`/`receive`, `claim`, `wait_next`, unbounded `read`, and any spin-until-peer loop count as waits/`blocks`, even if a backend uses CPU spinning. Alternative: treat spin as `no blocks` because it never parks; that would make the hot-path promise misleading and hide sibling waits from `parallel` analysis. **Unblocks:** truthful hot-path rows and the existing atomic-polling rule. **Reversibility:** semantic change is costly.

For generic `T`, inferred `Send`/`Sync` remains structural. Payloads cross tasks only when `T: Send`. Queue and sequencer *handles* may be `Send`/`Sync` as specified below, even when `T` is not `Sync`, because no mutable payload place escapes. Hooks used while publishing, copying, or dropping must be included in effects and may invalidate a claimed hot-path row; only an explicitly named callback such as `SeqLock.update` may execute user code while serializing writers. A `secret<T>` payload stays secret through failure and benchmark output.

## Recommended primitive surfaces

Sender: `.try_send(value) -> void | Unsent<T>`, `.send(value) -> void | Unsent<T>`, `.close() -> void`. Receiver: `.try_receive() -> T | Empty | Closed`, `.receive() -> T | Closed | Canceled`. Bounded per-slot sequence queue, not an unbounded channel alias. | Use `Channel<T>` with a new `.try_*` surface and no separate `Mpmc` type. | A Vyukov/crossbeam comparison and expert nonparking transfers; separate type spelling reversible, ownership and closure guarantees hard. |
| `Sequencer<T N>` | `sequencer<T N>()`; `.subscribe()` only before first publication gives a noncopyable `SequenceReader<T N>`; `.try_publish(batch) -> void | Unpublished<T>` / `.publish(batch) -> void | Unpublished<T>` reserve and publish an entire nonempty contiguous batch or none, with proven `0 <? batch.length <=? N`; `.close()`. Reader `.try_next() -> T | Empty | Closed`, `.next() -> T | Closed | Canceled`; every reader sees every published item in order, and the slowest reader's copy-out gates reuse. Each returned `T` is an independent value. | Public `.claim(n)`/`.publish(claim)` token plus explicit reader ack like the Disruptor. | Broadcast and batch publication without leaked claims that stall the ring; the all-or-nothing batch guarantee is hard to revise, member names reversible. |
| `SeqLock<T>` | `seqlock(value)`; `.try_read() -> T | Busy` takes one version check/copy/check attempt; `.read() -> T | Canceled` retries; `.store(value) -> void | Canceled` replaces a complete value, and `.update(f) -> T | Canceled | E` serializes writers while `f` computes the next value from the last complete value (`E` is `f`'s errors). The table's `Empty`/`Full` and `Unsent<T>` are proposed surface. `Busy` already exists for `try_lock`; reusing it for `SeqLock.try_read` is recommended. `N` is a compile-time type parameter for SPSC and Sequencer, while `Mpmc` uses a runtime capacity like `Channel<T>`; requiring a power of two is an internal layout choice, not a caller obligation. **Alternative:** put runtime capacity in all three constructors. **Unblocks:** static SPSC/Sequencer storage and early capacity proof. **Reversibility:** capacity syntax is reversible, compile-time versus runtime type identity is not.

### Ownership, copying and memory safety details

- **SPSC:** `split` consumes the queue; each endpoint is move-only, `Send` if `T: Send`, and not `Sync`. The unsplit queue is `Send` but not `Sync`. This prevents a copied sender from silently violating the single-producer algorithm. A send/receive is a release/acquire handoff; index caches and padding are private representation. `try_send`/`try_receive` are wait-free for the two designated endpoints, subject to payload copy/move hooks. Alternative: runtime endpoint leasing. **Unblocks:** safe Rigtorp-style specialization. **Reversibility:** cardinality is fundamental.
- **MPMC:** the handle is copyable and `Send`/`Sync` when `T: Send`; slots become uniquely owned after the winning CAS. `try_*` are lock-free, not wait-free: a caller may repeatedly lose a CAS to competitors, so `no blocks` does not imply a latency bound. No fairness or strict cross-producer ordering claim. Alternative: mutex-backed bounded ring with the same API; viable fallback but `try_*` could not honestly claim the lock-free hot-path contract. **Unblocks:** broad producer/consumer topologies. **Reversibility:** implementation yes, progress guarantee no.
- **Sequencer:** writers may be concurrent; each successful publish gets a contiguous sequence interval and becomes visible to readers only after every item in the batch is initialized and every earlier interval is complete. A failed publish returns the whole batch in `Unpublished<T>` with `Full`/`Closed`/`Canceled` reason. Cancellation is checked before reservation; once reserved, the trusted core completes publication or emits skipped tombstones on internal failure, without running user code. Readers skip tombstones, copy an item before advancing their cursor, and backpressure producers at the slowest cursor; `close` drains all published items. `T` must be `Send` and copyable; hook cost belongs in the row and any copy needed before reservation is charged to the caller. The sequencer and reader handles are `Send`, and the sequencer is `Sync`; each reader is noncopyable and not `Sync`. Do not accept arbitrary subscription after publication until replay/start-position semantics are decided. Alternative: public claim tokens and read-only ring views avoid copies, but cancellation/drop of a claim must publish a tombstone and reader lifetimes must gate slot reuse. **Unblocks:** a safe first broadcast primitive and honest Disruptor comparison. **Reversibility:** later zero-copy API can be added; changing broadcast to work sharing cannot.
- **SeqLock:** restrict `T` initially to compiler-verifiable fixed-size atomic-copyable layouts (plain scalar/record/array bits, no raw aliases, handles or lifecycle hooks). The trusted core reads and writes each payload word atomically; an odd/even sequence plus acquire/release validation rejects torn snapshots. An ordinary non-atomic copy concurrently with a writer would be a data race even if a later version check rejected it, so it is forbidden. `read`, `store`, and `update` are cancellation points before completing a snapshot/acquiring writer serialization; cancellation returns `Canceled` with no write. `update` callbacks run under writer serialization and their effects/deadlock edges count. If a callback returns an error or exits early, the old complete value stays published and shielded cleanup restores the even version/releases serialization. `SeqLock<T>` is a copyable `Send`/`Sync` handle when `T: Send` and eligible. Alternative: double-buffer immutable versions for all `T`, which overlaps `Snapshot<T>` and changes latency/storage. **Unblocks:** actual safe snapshot reads. **Reversibility:** broadening eligible `T` is easy; accepting unsafe `T` first is not.
- **Snapshot:** `T: Send + Sync` and structurally *deeply immutable* while published: no reachable mutable shared handle such as `Mutex`, and no hook that mutates the published object. This may need a compiler-derived `Freeze` property later; do not silently equate it with `Sync`. `Snapshot<T>` is a copyable `Send`/`Sync` handle; `SnapshotReader<T>` and `Version<T>` are move-only `Send`, not `Sync`, because each owns one pin slot. `reader()` establishes a hazard/epoch slot outside the hot loop; `load` pins before dereferencing and retries if publication races, never reading freed storage. A `Version<T>` points to immutable storage and cannot provide a mutable place. Each reader permits one live `Version` at a time; the version is scope-bound to that reader, and its last use unpins before another load or reader drop. Two simultaneous versions need two registered readers. `publish(value)` prepares the new version before one release/acquire pointer swap, then retires the old one; it may reclaim unpinned retired versions with visible drop-hook effects. `collect` deterministically reclaims those safe now, never waiting for pinned readers; final owner cleanup reclaims the rest once all readers are gone. Reader/version release itself does only bounded atomic bookkeeping; no hidden reclamation or user drop hook in `load`. `load` can meet `no blocks & no allocates` after registration; `.value` must carry `T`'s copy effects. Alternative: refcounted loads with a global mutex/retain handshake, simpler but not a proven hot-path read. **Unblocks:** cheap stable reads of nontrivial values. **Reversibility:** reclamation implementation yes, immutability no.

These are semantic recommendations, not proof that every backend can meet them. On a target without lock-free required atomics, either choose an implementation that still meets the advertised effect/progress row or reject that instantiation in a strict hot-path scope. Do not silently substitute a parking mutex. The ordinary library may still offer a slower implementation with a visible `blocks` row. **Alternative:** promise portable availability and weaken `no blocks`. **Unblocks:** honest cross-target contracts. **Reversibility:** target coverage may expand later; weakening a shipped row is hard.

## Operation-based `select`

**Recommended form** (new contextual `select` keyword; arm heads are recognized communication operations, not normal calls):

```dewy
let answer = select {
    item = inbox.receive() => match item {
        <Closed> => "done"
        value:int64 => "got {value}"
    }
    sent = outbox.send(next) => match sent {
        <Closed> => "peer closed"
        _ => "sent"
    }
    _ => "nothing ready"        # optional, makes the selection nonwaiting
}
```

Alternative spelling: `match select(inbox.receive() outbox.send(next)) { ... }` returning a tagged operation result. It composes with ordinary `match`, but requires first-class suspended-operation values and tags before there is evidence they are needed. **Unblocks:** a concise multi-channel wait now; tagged first-class operations can be added later. **Reversibility:** contextual spelling yes; commit semantics no. Only `Channel.send/receive` are required in the first slice; expert queue/sequencer operations join through the same reviewed selectable registration interface, not by running arbitrary callbacks or half-run futures. Alternative: make all blocking operations selectable at once; this multiplies the trusted core before the channel case is proven. **Unblocks:** incremental implementation. **Reversibility:** widening eligibility is easy.

Evaluation: inspect arms in source order; evaluate each receiver and send payload expression exactly once into stable temporary storage before registration. No arm head performs communication yet. Only the selected send consumes its payload; losing temporaries are cleaned up normally, and a live source variable is conditionally moved only on the winning path. An implementation unable to represent that move must reject that shape rather than copy a move-only value or consume a losing one. An arm binder always gets one outcome value: for `send`, success maps its `void` to `none`, while `Closed` remains `Closed`; for `receive`, it gets `T | Closed`. This mapping is local to `select`, not a change to ordinary `void | E` expressions. Arm bodies run once, **after** the selected operation has resolved. No arm body runs under an internal queue lock. Alternative: evaluate only the chosen arm's arguments, which changes observable evaluation order and can leave a selected send without a ready payload. **Unblocks:** predictable effects and move safety. **Reversibility:** very hard.

Exactly-one-commits: one claim shared by all registrations wins at one linearization point; at most one send/receive mutates a channel or queue, even if several arms target the same object. Losing registrations are removed before returning. If several are ready, rotate/randomize the probe order to avoid source-order bias, without promising starvation freedom. With `_`, choose it only if no communication arm is ready at the observation point. Without `_`, register atomically against wakeups and suspend; no missed readiness race. A close makes the affected arm ready with `Closed` (receive only after buffered data drains). `select` is a cancellation point even when `_` is present: cancellation observed before a commit returns `Canceled` for the whole expression, commits nothing, and runs no arm; a commit that wins the race remains committed. This preserves the decided level-triggered rule. Alternative: cancellation chooses an arm like Go's context channel; it can accidentally lose to a ready data arm after cancellation. **Unblocks:** precise cancellation and close tests. **Reversibility:** hard.

`select` arms follow ordinary value `match`/`if` arm rules: a one-value context requires one value from every arm; a collector may gather several values; a multi-valued binding or call consumes an arm's fixed count, and incompatible counts diagnose normally. The optional `_` is a readiness fallback, not a wildcard for payload values. A payload `T | Closed` is handled by `match` inside the committed arm, and `Canceled` remains an alternative of the whole `select` result. Example of a multi-value result: `let (source item) = select { x = a.receive() => ("a" x); y = b.receive() => ("b" y) }`, provided each arm narrows `Closed` first. Alternative: force every `select` to yield a tagged record, then `match` externally; this adds wrapping/allocation pressure and breaks direct multi-values. **Unblocks:** consistency with the decided multi-expression rules. **Reversibility:** surface choice yes, expression arity semantics hard.

Go's `select` is the closest surface precedent: its specification evaluates channel operands and send right-hand sides once in source order, chooses one ready communication pseudo-randomly, and its `default` executes when none is ready. Go panics on send to a closed channel; Dewy returns `Closed`/an unsent value. [Go specification](https://go.dev/ref/spec#Select_statements). Concurrent ML's `choose`/`sync` makes events first-class and composes them before synchronization; Dewy should borrow its atomic choice principle but defer first-class events and `wrap`/abort hooks until a real protocol needs them. [Reppy, *First-Class Synchronous Operations in Standard ML*](https://ecommons.cornell.edu/entities/publication/de1206e6-3dfb-48b9-99e2-f3146d25e507), [Parallel Concurrent ML](https://www.microsoft.com/en-us/research/wp-content/uploads/2009/09/Parallel-Concurrent-ML.pdf). **Unblocks:** composable future extension without importing CML's whole event model. **Reversibility:** adding event values is easy; accepting half-run futures as selectable would conflict with the adopted rule.

## Effects, wait analysis and certificates

| Operation | Proposed effect/certificate treatment |
|---|---|
| SPSC/MPMC `try_send`/`try_receive`; Sequencer `try_publish`/`try_next` | No `blocks`; capacity/emptiness reported as values. Count payload hooks and any real allocation. A user loop retrying until peer progress is an atomic-poll wait in the existing analysis, not an escape hatch. |
| SPSC/MPMC `send`/`receive`; Sequencer `publish`/`next` | `blocks`; `Canceled` is possible. Add wait nodes: full queue → drainer, empty queue → filler, full sequencer → slowest reader, empty reader → publisher. Close/cancel can discharge edges, but no certificate follows from a possible timeout. |
| `SeqLock.try_read` | No `blocks` and no `allocates` for eligible `T`; `Busy` if an odd/change version is seen. Never spin until a writer yields. |
| `SeqLock.read` and `store`/`update` | `read` is a wait on writer progress (`blocks`), including an unbounded retry loop. Writers have mutex-like order edges against one another. All three are cancellation points; `update`'s callback is analyzed while writer serialization is held; self-read, hidden calls, and cleanup count. |
| `Snapshot.reader` / `load` / `publish` / `collect` | Registration and publication allocate unless a prepared/preallocated form proves otherwise. A registered reader's `load` is nonparking and can be `no blocks & no allocates`; it may retry after an interfering publication. `publish` and `collect` can run visible drop hooks; `collect` does not wait for readers and reclaims only currently safe retired nodes. No task dependency edge for `load` or `publish` absent a hook wait. |
| `select` | Without `_`, one **disjunctive wait**: the select blocks only if every arm cannot commit. With `_`, no wait edge, though operand evaluation may have effects. Selected send/receive still has its channel effect and `Canceled` alternative. Source-order arm effects and losing-temporary cleanup count. |

The default lock/channel analysis should reuse its existing task, handle-identity and wait-event indexes, adding endpoint/sequencer identity and an OR-node for `select`; do not lower each arm to a fictitious sequential wait, which creates false cycles. A real cycle requires every arm of a blocked `select` to be blocked by the same dependency set. Preserve the current rule: demonstrated cycles are errors; unknown identities/counts are warnings. In a `parallel` body, a blocking primitive call or retry loop waiting for a sibling remains an error. **Alternative:** ignore expert waits in the default graph and rely on runtime testing; misses the same bounded cycles already caught for channels. **Unblocks:** consistent diagnostics. **Reversibility:** internal model can improve; unsound certificates cannot.

Under `$no_deadlocks`, no raw SPSC/MPMC/Sequencer blocking wait or raw blocking `select` receives a certificate merely from being in a library. Require an existing certified protocol (`serve`, `pipeline`) that owns the operations and proves capacity, drainer/filler and lifetime dependencies; `select` needs an explicit protocol proof that at least one arm can progress, with every selected continuation and hidden hook certified. Until that proof exists, reject it with the first missing wait witness. Nonwaiting `try_*`, a `select` with `_`, `SeqLock.try_read`, and `Snapshot.load` need no wait certificate, but their callers' retry loops may. `SeqLock.read` requires a writer-progress certificate; `update` follows checked lock order and rejects a callback waiting on itself. A lock held across a queue wait or blocking `select` is rejected as for channels. `collect` is checked for hook waits; cleanup remains shielded but not exempt. **Alternative:** certify all lock-free primitives by name; this confuses lock-free memory progress with absence of task-level deadlock. **Unblocks:** sound `$no_deadlocks` composition. **Reversibility:** adding certificates is easy; retracting a false theorem is not.

Keep the new analysis demand-driven: allocate identities/OR nodes only in bodies using these primitives or in a `$no_deadlocks` scope, summarize calls and hidden hooks once, and index waits by task and object. `select` with `k` arms adds O(k) registration/wait facts; cycle reachability may use the existing bounded solver, with budget exhaustion a warning in ordinary code and an error under `$no_deadlocks`. Measure dormant and active instruction cost on the flagship panel before landing, as the design docs require. **Alternative:** a separate whole-program primitive pass; it duplicates scans and breaks the compile-speed budget. **Unblocks:** capability without taxing unrelated programs. **Reversibility:** internal choice.

## Trusted core, checks and benchmarks

Trusted core: atomic ring-slot state, memory ordering, endpoint transfer, selection claim/registration/wakeup, sequencer publication bitmap/cursor gating, seqlock atomic word snapshots, and Snapshot hazard/epoch pin and retirement. These are the only components allowed to assert machine facts that Dewy cannot prove; review their invariants at the unsafe boundary. Dewy library code owns constructors, capacity obligations, result/error mapping, ordinary wrapper methods, `Version`/endpoint lifecycle contracts, and certified protocols. Wrapper code may not relabel a parking call as `no blocks`. Alternative: implement all primitives in an opaque native library; easier initially, but hides effect and ownership edges from the compiler and model checker. **Unblocks:** narrow audit surface. **Reversibility:** implementation placement yes, trust obligations no.

Nightly gate proposal: run a [GenMC](https://github.com/MPI-SWS/genmc)/loom-style explorer against the **actual instrumented atomic core** and Dewy wrapper state machines, not a separately maintained toy implementation. GenMC consumes LLVM IR, so this requires an instrumentable lowering of the same core; until that exists, a handwritten reference model is useful research but cannot certify the implementation. Explore capacities 1–3 and two/three tasks; all short producer/consumer interleavings, CAS failures, wraparound near the integer boundary, close versus send/drain, cancel versus commit, duplicate select arms, multiple ready arms, claim cleanup, seqlock writer/reader races, and Snapshot publish/pin/reclaim races. Check linearizability (one dequeue per item; exactly one select commit), FIFO/broadcast ordering, no uninitialized or freed read, no lost wakeup, eventual release after close/cancel, and no leaked ownership. Bound each scenario to a finite operation count; report the explored bound and any timeout as **gate failure**, not success. Allocate 30 minutes wall time nightly total, at most four workers and 5 minutes each for six families (SPSC, MPMC, Sequencer, SeqLock, Snapshot, channel/select); store traces as CI artifacts, not repository evidence. Use a second stress/TSan pass for longer executions, clearly separate from bounded exploration. Loom's own documentation says it does not cover the full C11 model, so passing loom alone is not a proof of every target memory ordering. [Loom documentation](https://github.com/tokio-rs/loom). Alternative: randomized stress alone; useful but misses rare weak-memory schedules. **Unblocks:** a repeatable safety gate. **Reversibility:** time budget/tool can change, required invariants should not.

Benchmark contract (quiet, pinned dedicated machine or CI runner for wall-clock; same capacity, item layout, batching, placement, compiler optimization, warmup and traffic shape; no more than four workers on the shared host, and run 4×4 only on the dedicated machine):

| Dewy kernel | Primary baseline and fair comparison | Report |
|---|---|---|
| SPSC single-item throughput and two-queue round trip, capacities 1/64/4096 | [Rigtorp SPSCQueue](https://github.com/rigtorp/SPSCQueue), same payload and pinned two-core placement; it specifically caches peer indices. | items/s; p50/p99/p99.9 round-trip ns; full/empty rate, allocations and cycles/item. |
| Sequencer one producer/one reader plus 1→2 and 1→4 fan-out, batch 1/16/64 | [LMAX Disruptor](https://lmax-exchange.github.io/disruptor/user-guide/) with equivalent producer mode, gating and wait strategy. Compare single-reader SPSC-like path separately from broadcast; do not claim its broadcast is a queue. | publications/s, delivered items/s, p50/p99.9 publish-to-read, slowest-reader backpressure. |

Recommend initial ship targets ≥0.9× baseline throughput for like-for-like SPSC/MPMC and ≤1.25× Go ping-pong p50, with no correctness or tail-latency regression hidden by the median. These are proposed gates, not measurements or existing decisions; if a decided primitive misses, profile and redesign rather than waive its safety contract. Disruptor fan-out and seqlock/Snapshot have different contracts, so establish named baseline kernels first and gate subsequent regressions against them. Alternative: no numeric target until the first pilot; safer against premature tuning but weak as an acceptance test. **Unblocks:** a measurable stage-4 completion criterion. **Reversibility:** thresholds are adjustable before baseline approval.

Acceptance cases to accompany implementation: capacity-one wrap/full/empty and move-only failed sends; copied MPMC handle with concurrent close; SPSC endpoint duplication rejected; sequencer batch cancellation and slow subscriber; seqlock torn-read litmus and writer callback self-wait; two Snapshot versions held by two readers across publication/reclamation; `select` duplicate arms, both-ready arms, close/cancel at commit, losing move-only send, and multi-value arms; default warnings and strict `$no_deadlocks` rejection for raw waits, with a certified protocol positive. These are proposed cases, not tests run in this design round. **Alternative:** only throughput and happy-path tests; leaves the ownership and interleaving claims unverified. **Unblocks:** a concrete implementation review. **Reversibility:** cases can expand; safety coverage should not shrink.

### Consistency flags for the coordinator

- The adopted text says `Canceled` is an alternative on every blocking operation, but the implemented `Mutex.lock` is expressly not a cancellation point. Recommend that all *new* blocking operations above return `Canceled` and that David resolve the existing `lock` exception in a separate review; alternative extend the mutex exception to seqlock writers. Unblocks one rule callers can rely on. Reversible for new API before release; changing existing `lock` may affect programs.
- Existing `Channel.send(value) -> void | Closed | Canceled` does not return the payload on failure, while the proposed expert queue `Unsent<T>` does. Recommend the lossless expert contract now and a later compatibility review of `Channel`, not an unrequested channel change in stage 4. Alternative mirror `Channel` exactly and accept that a failed move-only send can lose its value. Unblocks move-only queue payloads. Reversible only before programs depend on failures.
- The staged roadmap places deadlock diagnostics after the primitive library, but default channel/lock analysis and `$no_deadlocks` certificates are already built. Recommend extending those existing analyses in stage 4 instead of leaving new waits invisible until stage 7. Alternative delay all expert wait diagnostics. Unblocks consistency with the current compiler. Internal sequencing is reversible; silent certificate gaps are not.
