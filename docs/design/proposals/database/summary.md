# Native database — round 4 summary

[Round 4](round4.md) replaces the conditional-lambda design with a **library-only v1**. [Programs](programs-r4/) contain 15 complete specimens plus the charged CSV helper. [Regrade](dogfood-round4.md) cites every score. Earlier rounds/programs remain intact; prior summary/names are saved as summary-r3.md and names-r3.txt.

**Floor: 2 across the whole corpus**, because CSV import still needs a 73-line handwritten parser. **Database-focused floor: 3**, reflecting descriptor discoverability, limited schema evolution, local cursors/restore policy and application-written optimistic saves. No grade depends on future callable inspection. These are paper designs, not executed database tests or completed cold naming.

- Ordinary Dewy record types are storage values. `fields_of<T>` derives typed field objects using existing reflection; `eq/lt/ge/contains/all_of/tuple` build ordinary validated plan data. Indexes are automatic choices over explicit descriptors; local fallback warns at runtime. No comparison overload pretends to capture a bool expression.
- Compound keys have explicit tuple types. Programs 01/13 also show legal ordinary sorts with `(x):>[int string]`. Exact values, equality and stable order agree with Dewy; backend coercions cannot alter them.
- `related` filters through typed references. `include` returns each original post alongside its author, grouped tags and optional editor under one snapshot. Program 03 covers empty/multiple/shared tags. With batches large enough, its feed needs three data-fetch statements, not one per post.
- Scoped `task.tasks` owns inventory children; each owns its transaction. Unexpected failure cancels/joins siblings but does not undo prior commits. The ordinary function spelling remains D41's question. Explicit commit publishes; abandonment rolls back. D40 still owns cleanup details.
- Only entity selections mutate; update takes a constant typed patch. `require` removes repeated required-fetch boilerplate. Output size, logical visits, charged bytes and cooperative deadline are separate bounds; the CLI handles QueryLimit.
- Structural migrations have explicit intent, canonical plan hashes, a repeatable runner and collision-safe backups. Unsupported key/target/conversion changes fail before writes. Backups are read-only; writable restore creates a new lineage and remaps internal references. External refs/cursors must be reacquired.
- Count/sum use typed aggregate objects. Search pins literal-token behavior and tokenizer version. SQL remains separate: constant prepared text, bound parameters and checked typed rows.

**Essential v1 names:** storage `collection fields_of Ref open memory get require insert reference replace put begin commit rollback snapshot close`; query/relation `index unique tuple eq lt ge contains all_of where sorted all count page explain related include update delete`. Brief-complete modules add `group_by summarize sum`, `migration rename remove describe migrate`, `backup restore`, `full_text search`, and SQL `sqlite prepare all execute`. Options, result fields and errors are in [names.txt](names.txt).

**Can wait:** planned map/follow, mutation lambdas, custom aggregates, transform migrations, compare-and-replace, savepoints, OR/NOT builders, nested includes, direct query iteration, stateless web cursors, online migration and identity-preserving recovery. The first version is deliberately bounded; these omissions contribute to grades.

**What future inspection adds:** exact ordinary comparisons, boolean expressions, typed tuple callbacks and recognized projections could compile to the same plans, reducing descriptor ceremony and improving source diagnostics. Round 4 shows three pairs side by side. Inspection can expose a comprehension inside a callable handed to the library; an unwrapped eager comprehension additionally needs general iteration lowering or enclosing-expression access. Neither is necessary for this v1.
