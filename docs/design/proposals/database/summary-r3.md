# Dewy-native databases — one-page review summary

**Recommendation:** ordinary stored values, typed references, composable Dewy query expressions, explicit publication. SQLite first; preserve these logical contracts for a later Dewy engine. This is a paper design with **14 programs and 70 line-cited grades**, not an implemented library or an all-5 review.

**Final rules** (round 1, amended by rounds 2 and 3):

- A schema is a constant record of typed collection descriptors. Records remain ordinary values; loading never attaches implicit I/O or auto-save behavior. Store handles explicitly share external state.
- Keys, unique constraints and secondary indexes use typed selectors. Reference fields and sets of references get transactional reverse indexes. A blog's tags are an ordinary `set<Ref<Tag>>`; relation records are needed only when an edge has its own data. Deletion never silently cascades.
- Pure queries compose with `where`, `map`, `sorted`, `group_by` and `follow`. Execution is explicit. Preserve Dewy equality, optionals, exact arithmetic, stable order and multiplicity. Unsupported pure callbacks run locally with cost warnings; effects require ordinary materialized processing. Index selection never changes results.
- Pages retain their snapshot through their continuation. Output size does not bound work; `max_scanned` does. Tokens are local resources in v1. Group items are ordinary arrays, with ordinary `length` and `sum`; eliminating their allocation is an optimization requiring proof.
- Single mutations are atomic. `begin` gives serializable read/write work; `commit()` alone publishes. `$__abandon__ = () => …` rolls back every unfinished exit. A failed mutation poisons tx. Tasks share stores and own separate transactions. No automatic callback retries; uncertain publication is `CommitUnknown`.
- Open never migrates silently. Changes retain old/new schemas, explicit rename/removal intent and typed transforms. Migrations publish atomically and initially pause writers. Backups use a consistent backend snapshot, never a casual live-file copy.
- Native search treats input as literal terms. SQL is a separate first-class module with constant statements, separately bound values and checked typed rows. Native files never expose a writable raw connection that bypasses invariants.

**Floors:** indexed lambda translation needs a general typed callable-inspection contract. The exact eager comprehension additionally needs a general iteration-optimization contract; an iterator cannot inspect its caller's filter. Existing comptime field reflection supplies neither. This is a concrete language-design dependency, not a reason to abandon the target or accept database-specific compiler magic. Completeness remains **2 in the sharpest query cases**. Transaction safety is mostly **4** pending D40 and fault evidence; migration/search/remote-continuation workflows remain **3**. Independent name/discoverability testing has not occurred. Mandatory cyclic references and ambiguous same-type reference targets also need further design.

**Names:** proposed modules `database.dewy`, `sql.dewy`; collection/index/reference surface `collection`, `key`, `indexes`, `index`, `unique`, `full_text`, `language`, `Ref`, `reference`; query surface `where`, `map`, `sorted`, `group_by`, `follow`, `all`, `count`, `sum`, `explain`, `page`, `size`, `after`, `max_scanned`, `items`, `next`; storage/evolution `open`, `create`, `read_only`, `memory`, `insert`, `replace`, `put`, `update`, `delete`, `begin`, `commit`, `rollback`, `snapshot`, `close`, `backup`, `migration`, `rename`, `remove`, `transform`, `describe`, `migrate`; search `search`, `record`, `score`, `excerpt`; SQL `sqlite`, `prepare`, `execute`. Reused names have new receiver contracts. [names.txt](names.txt) includes every proposed error name and short usages. None is represented as cold-tested; application record/helper names are not a language naming proposal.
