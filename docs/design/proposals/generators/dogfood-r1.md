# Generator design dogfood, round 1

**Choose A, one value per advance.** A wins 09, 12 and 13. B wins 07 and 08 for forwarding fixed positional rows. The other eight programs tied. The fixed-shape B alternatives for 09 and 12 tie their A counterparts. Every task can use A with a tuple, array or named event wherever a logical item has several fields.

## Method and grades

The 13 workloads have paired source files. The game and export add fixed-shape B versions. The reply adds a shared owner-based version. The applications implement the production, traversal and stopping logic and state their boundary contracts for transport, storage or UI. The programs were read and traced against the design. The proposed syntax and disposal rules have no compiler run in this evaluation. For A, the comparison uses one value per advance, fixed-count eager bindings and explicit product or union values. For B, it uses round 1’s entry boundaries and pack rules. Both versions use the same demand, manual-step envelope, borrowing and cleanup rules where the specification offers them. No example needs cursor copying. [Round 1](round1.md).

Grades are 1–5 for obvious (readable behavior), discoverable (readily found syntax and protocol), concise (few incidental operations), safe by default (compiler-checked shape, lifetime and errors), and complete (can express the task). A 5 means no material friction on that axis in this task, 4 means a small cost or unresolved proof, 3 means a recurring rule or workaround, 2 means a substantial workaround, and 1 means the task fails on that axis. Safety grades assume the stated application contracts. The socket grades include the still-open fallible disposal design. “B, fixed” means one explicit union or record value per advance.

## Friction and handoff traces

1. **Reply preview and journal, both.** Registration belongs after the first successful reservation. The token counter must advance immediately before each infallible handoff. Passing the cursor by value to the preview loop ensures a limit break publishes before `finish_preview`. With tokens a/b/c and a limit of two, the trace is reserve, stage a, deliver a, stage b, deliver b, release upstream, publish a/b as partial. An actually drained reply sets complete after observing EOF. A failure in stage publishes the previously delivered prefix. A consumer failure after handoff includes that handed-off token. A borrowed break can leave publication pending for a subsequent resume. Factory-scope defer would run before first demand, and a trailing publication would miss break and error. The owner version packages the mutable prefix and completion flag, which makes registration automatic wherever the application reuses that owner. [Local registration](programs-r1/01-reply-a.dewy:11), [Preview ownership](programs-r1/01-reply-a.dewy:24), [Owner hook](programs-r1/01-reply-owner.dewy:6), [Owner staging](programs-r1/01-reply-owner.dewy:14).
2. **Rotated access logs, both.** The reader must distinguish EOF, malformed data, and a failed read. Forwarding every exception indiscriminately would also forward `none`. The typed suffix and explicit EOF branch preserve the distinction. The cutoff jumps out of both loops and relies on the declared global ordering. A valid cutoff crossing closes the current shard and skips older shards. A limit break releases the owned active shard before returning to the UI. An I/O failure forwards before the zero-match fallback. [Read and cutoff](programs-r1/02-access-log-a.dewy:13), [Early limit and fallback](programs-r1/02-access-log-a.dewy:32).
3. **Paginated catalog, both.** A page with zero active elements may still have a continuation. The same demand searches forward, bounded by page count. A successful final-page result needs a generator label because there is no generator-local `return`. Checking only that an inner loop entered would lose valid later pages. When the index quota is hit partway through a page, later pages are untouched. The API delivers whole decoded pages, so the stopped traversal has already paid for the current page. [Paging and stop](programs-r1/03-catalog-a.dewy:9), [Consumer quota](programs-r1/03-catalog-a.dewy:26).
4. **Recursive asset tree, both.** One missing `...` changes a yielded asset into a generator value and the explicit return type catches it. Recursion retains the active path and manifest snapshot. Work before a leaf and release of the active path scale with traversal depth, and a deep tree can require growable cursor storage. For a visible root with two eligible child directories, stopping at the first eligible leaf never enters the second child. [Typed recursive delegation](programs-r1/04-asset-tree-a.dewy:9), [Preview limit](programs-r1/04-asset-tree-a.dewy:25).
5. **Port-rule tokenizer and parser, both.** A parser needs manual stepping, a mutable place, and a separate success envelope, so `next_token` absorbs repeated unpacking. The lexer must terminate with an offset-bearing error for invalid bytes or an overflowing port. An inverted range is rejected before the parser asks for another token. Reading `8000-7999,443` leaves the old configuration and never tokenizes the comma. A token requires scanning all its digits, but scanning stops before advancing past its first nondigit. [Number scan](programs-r1/05-port-rules-a.dewy:19), [Manual step](programs-r1/05-port-rules-a.dewy:34), [Reject or commit](programs-r1/05-port-rules-a.dewy:53).
6. **Infinite retry plan, both.** A check at the head of an already-entered source loop would request an extra item. Skip entry for zero and break the lazy body immediately when resuming after the last requested output. A cap makes delay growth bounded and exact integer accumulation avoids a cumulative fixed-width overflow. The source is known infallible here, which keeps `take` small. A fallible generalization needs a separate resume/finalization contract. [Retry and cap](programs-r1/06-retry-preview-a.dewy:6), [Demand boundary](programs-r1/06-retry-preview-a.dewy:17).
7. **Meter pipeline, A costs conversions, B costs a grouping rule.** A needs a fixed value at source emission, spreads it into positional callbacks and collects the calibration pair into another tuple. B publishes the pair with doubled parentheses at the streaming arm, then forwards it unchanged through filter and chain, maps it through a two-result calibration, and passes it directly into the chart call. Replacing the doubly enclosed arm with one pair of parentheses emits two singletons and breaks the two-parameter filter. Draining either stream before charting would give up demand-driven processing. B wins here with existing positional helpers. With tuple-accepting helpers, A’s adapters can operate on one value throughout. [A tuple source](programs-r1/07-meter-pipeline-a.dewy:9), [A forwarding and mapping](programs-r1/07-meter-pipeline-a.dewy:16), [B grouping](programs-r1/07-meter-pipeline-b.dewy:9), [B forwarding and mapping](programs-r1/07-meter-pipeline-b.dewy:13), [B chart call](programs-r1/07-meter-pipeline-b.dewy:36).
8. **Ledger zip, A adds tuple construction and two spreads, B adds a grouped loop body.** B’s pair flows to the positional mismatch test and report. A’s tuple gives the same per-turn pairing and can be stored intact without an implicit expansion. Both require a preflight length check because the reconciliation contract rejects unmatched rows. Generic `and` requests left before right and can consume an unmatched left value if right ends. An earlier effect is irreversible. The snapshots here are pure and lengths equal, so no observable unmatched read occurs. With two already grouped inputs, B’s `((a b))` concatenates their fields. Explicit tuple or record members preserve which input each nested row came from. [A zip](programs-r1/08-ledger-zip-a.dewy:13), [A positional calls](programs-r1/08-ledger-zip-a.dewy:27), [B zip](programs-r1/08-ledger-zip-b.dewy:13), [B positional calls](programs-r1/08-ledger-zip-b.dewy:24).
9. **Game input, variable B.** The raw event is already an exact union. The pack version binds a runtime choice of widths 1, 2 and 3, then reconstructs meaning from arity and field types. Adding a second event with three integer fields would require an explicit discriminator or a protocol revision. Nominal variants accept overlapping field types with exhaustive dispatch. All versions stop polling on quit and leave any post-quit event queued. The frame budget counts polls, including skipped zero deltas. [B eager shape choice](programs-r1/09-game-input-b.dewy:14), [B structural dispatch](programs-r1/09-game-input-b.dewy:26), [Fixed B dispatch](programs-r1/09-game-input-b-fixed.dewy:21).
10. **Mixed monitor replay, both.** `none` is a useful offline payload, and treating a bare payload as a step would confuse it with EOF. The singleton envelope preserves a real union value. With inputs offline, delta, EOF and budget one, the first chunk clears the measurement and leaves the cursor live. The next chunk applies the delta. Only a subsequent advance observes EOF and finishes. An exact budget boundary therefore pauses until a later request. The cursor needs to stay with the session and the chunk borrows it. [Offline output](programs-r1/10-monitor-replay-a.dewy:9), [Borrowed chunk and EOF](programs-r1/10-monitor-replay-a.dewy:18).
11. **Abandoned inventory socket, both.** Fallible disposal needs two explicit boundaries, one for consumption failure and one for owner release. Breaking the borrowed loop leaves the socket open until the marked scope ends. If that close fails, it prevents `ui.finish`. A read or consumer failure combined with close failure must retain both. A trailing close misses abandonment and errors. The program is conditional on marked, checked drop and combined failure from D40/D42, with cancellation handling from D44. [Acquisition](programs-r1/11-inventory-socket-a.dewy:9), [Marked owner scope](programs-r1/11-inventory-socket-a.dewy:20), [Close failure witness](programs-r1/11-inventory-socket-a.dewy:31).
12. **Channel export, variable B.** An eager binding collects the identifier and all samples before the contribution is ready. The variadic wrapper repacks the remainder into the array the writer already knows how to consume. This is the strongest legitimate unknown-width call: one fixed prefix and a homogeneous unbounded-in-type suffix, all accepted by one signature. It still adds an intermediate representation and may require storage unless optimized. The fixed form hands the writer the original sample array in the original transaction. Both send an online channel of width zero once. The B prefix ensures the row is nonempty since an empty pack would produce zero turns. [B variadic signature](programs-r1/12-channel-export-b.dewy:9), [B eager collection](programs-r1/12-channel-export-b.dewy:19), [B forwarding](programs-r1/12-channel-export-b.dewy:28), [Fixed B handoff](programs-r1/12-channel-export-b-fixed.dewy:15), [Fixed B writer](programs-r1/12-channel-export-b-fixed.dewy:23).
13. **Recorder frames, B needs an explicit split, A retains a pending value.** The two results come from a storage layout. The consumer works at sample granularity. A places the eager decoder directly in the streaming body and publishes its two keys in separate steps. B needs a fixed unpack and two entries. A still computes the full eager pair before the first handoff and keeps the second key pending while suspended. Extracting a streaming pair into an eager helper can change latency in either option. Moving two effectful expressions from sibling entries into an ordinary grouped entry delays the first handoff under B even without extracting a helper. [A eager call](programs-r1/13-recorder-flags-a.dewy:17), [B split](programs-r1/13-recorder-flags-b.dewy:17), [Early return](programs-r1/13-recorder-flags-a.dewy:23).

## Decisions

### One value per advance

Fixed-width positional forwarding gives B tangible gains in 07 and 08. Those gains fit a local tuple or record in A, and the extra A syntax appears only where a positional call must unpack it. B’s body-versus-entry rule affects demand even in ordinary code. In a streaming body, `summary(entry) detail(entry) or_throw` can deliver a summary before touching detail. Put a group around the same two expressions in entry position and B evaluates both before handoff. A keeps the handoff after summary when the literals are streamed. An eager ordinary helper still runs to completion under A, as the recorder case shows. Prefer A’s uniform item boundary. Preserve regrouping through eager collection and fixed positional calls where the count and shape are statically proved. [A meter conversions](programs-r1/07-meter-pipeline-a.dewy:16), [B meter forwarding](programs-r1/07-meter-pipeline-b.dewy:13), [B zip row](programs-r1/08-ledger-zip-b.dewy:14), [A recorder handoff](programs-r1/13-recorder-flags-a.dewy:17).

### Variable runtime arity

Keep fixed-count eager bindings. In 09 the two- and three-field alternatives carry less domain information than the original names. In 12 the unknown-width tail fits a genuine rest-argument API, but the caller already owns the exact array the writer needs. An eager collector, a stream of unknown length, and a union of explicit values cover all tested needs. Call arity and overload selection can stay static. If a future input protocol literally describes widths without domain event names, an explicit array retains those widths and permits checked validation at the receiving boundary. [Game shape choice](programs-r1/09-game-input-b.dewy:14), [Game nominal match](programs-r1/09-game-input-b-fixed.dewy:21), [Ragged rest call](programs-r1/12-channel-export-b.dewy:28), [Array writer](programs-r1/12-channel-export-b-fixed.dewy:23), [Audit finding 1](audit-r1.md:7).

### Cleanup

Resumable destruction is necessary for 01, 02 and 11 under both advancement rules. 01 loses the audit prefix, 02 can leak a shard reader, and 11 can leak a socket or lose a close failure. In 03 the response owner closes inside the page fetch before handoff. A streaming-response variant would need the same frame cleanup. 10 deliberately retains the owner across UI chunks. A temporary borrow ending is insufficient to signal abandonment. On an owning exit, run active child cleanup and each registered frame duty exactly once. Destruction of a never-started cursor releases acquisitions captured at construction, while body-local duties begin only after their registration runs. Test consumption, break, consumer error, read error, cancellation, and drop-before-demand separately. [Reply registration](programs-r1/01-reply-a.dewy:11), [Shard acquisition](programs-r1/02-access-log-a.dewy:10), [Response ownership](programs-r1/03-catalog-a.dewy:3), [Borrowed replay](programs-r1/10-monitor-replay-a.dewy:18), [Socket scope](programs-r1/11-inventory-socket-a.dewy:20).

Keep the checked, infallible local `defer` provisionally. The reply shows it reading producer-private progress directly with one registration. The hook on `ReplyTicket` achieves the same guarantee and enforces reuse, at the cost of packaging the slot and both state fields into an owner. Use that form for broadly reused obligations. A fallible socket close needs checked owner disposal, and a durable potentially failing journal write would need its own checked completion contract. [Local defer](programs-r1/01-reply-a.dewy:11), [Owner and staging](programs-r1/01-reply-owner.dewy:5), [Fallible disposal](programs-r1/11-inventory-socket-a.dewy:27).

### Loop shorthand

Use `lazy loop i in xs body`. Round 1’s full-expression form already accepts it. The added shorthand removes exactly `loop` and one space per site. The corpus uses this form at three corresponding declaration sites, one in the meter source and two in the reconciler. Compare `lazy loop cents in expected cents` with `lazy cents in expected cents` and the equivalent multistatement statement source. Neither variant changes scope, stop behavior, output or grouping. The explicit keyword makes the existing loop form, including combined headers and fallback rules, recognizable at first read. A small spelling saving did not earn a second parser form here. [Meter loop source](programs-r1/07-meter-pipeline-a.dewy:9), [Both ledger loops](programs-r1/08-ledger-zip-a.dewy:8).
