# Dogfood: final round, with line evidence

This is an author paper review of 20 contextual programs, not a compiler run, independent review, user study or performance benchmark. All library imports except fixtures name proposed APIs. Expected successes/failures are contracts to test later. The ordinary compiler cannot validate these files yet. No score treats a prose promise as an implemented safety proof.

Scores: **O** obvious, **D** discoverable, **C** concise, **S** safe by default, **F** complete. 5 means the demonstrated source/contract has no identified ergonomic defect on that axis; 4 is useful with one meaningful caveat; 3 needs substantial machinery or workarounds; 2 misses a stated use; 1 would be unusable or unsound. Safety 5 for a negative case means the specified refusal avoids a wrong result, not that compiler enforcement has been tested. Completeness includes actual missing mechanisms, so no program gets F5. These are Dewy's comparative grades against the six concrete reference workflows below, not benchmark scores for entire languages.

The five-score vector does not average away a blocker. The floor is **2**: the exact fallible database comprehension and two unsupported AD paths. Core indexed lambdas are promising, but this paper does not earn “gold standard” or “ready to accept.”

## Why the remaining sub-5s are not erased by another wording pass

Discoverability needs cold readers and usable signatures/diagnostics. This assignment is a sub-agent design pass, not authorization to fabricate that evidence. The type and hook names remain candidates.

Assertion concision could be improved with an expression-taking macro/tag, but that would add a new quotation/expansion boundary beyond the proposed single hook and revisit the existing macro exclusion. Keep the honest thunk cost visible instead of silently using unapproved syntax.

Exact fallible one-line collection needs a general iterator/error decision; a planner cannot type-check a field on an error value. General branch/opaque AD, full scalar/backend support, verified effect/totality summaries and a robust heterogeneous plan API need actual additional capability. Some can be designed and implemented in later bounded slices, but calling them complete in this paper would violate the scope and evidence requirements. Arbitrary equivalence/termination cannot be solved by promising a clever compiler.

Safe defaults are specified, but unimplemented stubs/validators/diagnostics and backend behavior prevent a 5 on the translated positive cases. Tests and an independent review could expose further defects. No measured advantage over C#/Scala/Julia/Zig/Rust/Python has been established.

## Manual checks and future execution gates

The arithmetic oracles were checked independently: wrapped 0xffffffff*3+1 = 4294967294; the two-sample loss has slope 10w−26, giving −6 at w=2; calibration x²+3x gives 7 at x=2; a frozen threshold of 0 selects a/c after the outer variable changes. These are mathematical checks, not execution of proposed Dewy modules.

Positive specimens: 01–07, 10–12, 16, 18–19. Intended runtime failures: 08–09, 14–15. Intended compile rejections: 13, 17, 20. Program 03 succeeds only with the checked summary requirement explained in round 3; an opaque callback with no such summary must fail. Fixture code is setup and not counted as a 21st scenario.

Before a real implementation can claim these outcomes: compile positive/rejection cases with exact diagnostics; compare optimized/unoptimized execution; test failure and cancellation edges; test hidden captures and secret spans; adversarially test optional/huge-int/IEEE semantics; exercise nested budget exhaustion; and measure compile instructions and code size. Do not run today's compiler and mistake missing-module diagnostics for semantic validation.
