# Handoff: combining failures, round 4

**Recommend `a & b` for a pair, returning one `errors.ErrorGroup`; use `errors.join(failures...)` for zero/one/many. This is not a promise that the result type is `A & B`.** [Round 4](round4.md) is the current recommendation. Its opening five examples cover combining, extracting, accumulating, origins and cleanup, each inside a function. Historical rounds and the independent review remain unchanged.

The previous summary's argument that intersection types cannot retain order or duplicate occurrences was wrong and is withdrawn. A carrier can retain `[a,b,a]` while its type normalizes to A & B. Round 4 specifies that true-intersection candidate seriously: left canonical shared-field projection where all constraints hold, nominal matching of both kinds, whole-value selected handlers, cancellation carrying, exact parts and seeded accumulation. It then identifies the actual limits: incompatible singleton/shared-field types have no common projection; an ordinary A fallback can consume unrelated B; and Canceled intersected with an ordinary error subtype also satisfies error. Faceted records or partial handlers could change that, but require a broader semantics decision. [round4.md:79](round4.md) [round4.md:87](round4.md)

The group-returning operator is total across child payload shapes under the stated allocation assumptions, preserves order and duplicates, gives a generic group `.message`, and exposes exact immediate `.errors`. It is eager, not a fail-fast sequence. `acc &= e` works with a nonempty seed stored as exception; an initially empty batch uses an ordinary array and join. If a literal intersection return type is indispensable, prefer join for general failures rather than silently weaken the existing intersection contract. [round4.md:137](round4.md) [round4.md:145](round4.md)

One group is sufficient: **ErrorGroup holds several failures, possibly including cancellation; inspect it as an exception.** It derives from exception, outside error. ExceptionGroup is removed. The cost is explicit: even an all-ordinary group does not match error or pass to an error-only parameter. Widen reporting APIs, explicitly select ErrorGroup, or use bare or_throw. Ordinary is?/match/typed handlers remain outer-kind operations. `??<FileError>` does not consume a containing group. Carrying cancellation still passes through bare ?? and defaults that do not explicitly acknowledge both Canceled and the group. The descendant-aware `or_throw<Canceled>` exception remains a discoverability cost. [round4.md:141](round4.md) [round4.md:159](round4.md)

M1 is fixed by a proposed ordinary-library `errors.recover<E>(failure @repair)`: incoming cancellation returns the exact original before any callback; task cancellation is ordered against every callback start; unmatched and unattempted leaves remain, and failed repair retains both the original and new failure. Cancellation after the last successful repair cannot turn into success. An already admitted callback follows cooperative cancellation; no rollback or arbitrary-instruction interruption is promised. The helper removes the application's split/rest/stop-flag protocol. Selected move-only payloads are excluded from v1 until a borrowing contract exists. This new name is provisional and **was not cold-read**. [round4.md:196](round4.md) [round4.md:200](round4.md)

Incoming cancellation produces zero callbacks and preserves the exact input; the modeled schedules cover entry, before/after callbacks and final success. No Dewy or peer programs were compiled or executed. Static checks passed for 173 file/line links, all thirteen program files, and exclusion of deferred APIs/placeholders from their code.
