# Independent regrade: runtime-chosen settings, round 1

Graded without reading dogfood.md. Axes: O obvious, D discoverable, C concise, S safe by default, P complete.
The design is `round1.md`; my extra programs are in `programs-regrade/` (R1 library cap under a tighter caller plus a handler table, R2 `$runtime_checks` from a flag, R3 per-request zone and memory cap in a parallel server with outliving tasks).

Floor: 2 (programs 02, 07, 10, R1, R2, R3). The idiom itself (01) works, but the rules around it leave the common edge cases undefined or contradictory.

## Must-fix

1. **Body-level prefix scope contradicts the entry-point rule and LANGUAGE.md.** `main = () => { $program.max_cores = 1 \n work() \n $program.max_cores = 2 \n work() }` (06): today tags in `main` are program-wide and a second one is a duplicate error. Design 06/10/05/13 work only because the tag is directly above its one statement. Decide: tags at the head of a block cover the block, or a prefix must precede a block or call, and say what `$x = v` followed by `let a = f()` followed by `use(a)` does.
2. **Inner-above-outer cap is a compile error for literals but a run-time refusal for values and function values.** R1: `indexer.index` (8) under `laptop` (2). A library cap then becomes semver-breaking and the handler table behaves differently from the direct call. Make an inner cap only narrow (effective = min, as `$parallel` ceilings already do), and warn only on a same-package conflict.
3. **Memory frame accounting is undefined at the edges.** R3 `page_for` returns an allocation made under a 32MiB frame to a 512MiB frame; "a fresh call starts at zero" conflicts with "counts against any outer ceiling". Define transfer on return, release on free, arena/stack allocation, and whether parallel iterations share one budget. The cost paragraph ("nothing else pays") is wrong: every allocation under a memory frame needs a frame tag and, with parallel tasks sharing a frame, an atomic.
4. **Outliving tasks.** R3 `app.spawn(@audit(r app))`: say whether children of a task inherit the frame (transitive), what keeps the frame alive after the caller pops it, and that the intro sentence "After that call returns, the cap is gone" is false for tasks. Same for policy frames (`today` in `audit` after `handle` returned).
5. **`$runtime_checks = flag` is illegal in its main use case** (R2). State it as a rule with the error text, or provide a legal path (the checked body stays, the plain body is allowed only where all indexes are proved) and move the example in the doc from "debug flag" to "performance switch for proved code".
6. **Dynamic cap values are unvalidated.** 10: `$program.max_cores = cores` with `cores:int` and no outer cap has no stated check for `cores <? 1`; the "proved after the guard" case does not cross the call to `play`. Require a refined parameter or a stated run-time check, and say what zero or negative does.
7. **Function values and variants.** R1 handler table: "a call it cannot tie to a variant is a compile error" makes every table of handlers called under two code vectors unusable; either a function value carries all variants and the call picks by frame, or say so and give the cost.

## Should-fix

- Header versus prefix depends on whether the next declaration is a function: inserting `User:type = ...` between the tag and `laptop` silently turns a per-function cap into the process default (01, 03). Needs a marker or a rule that a `$program` tag directly above a function is always its prefix (then the header goes before imports).
- Warnings fire on correct code: 06 (`parallel` under three caps), R3 (`today` in a parallel loop), 07 (a task with a different cap still running). Warn only when a value could not be folded and the build asked for speed.
- `$fast_math` (11) over a dynamic extent changes library code the caller never wrote; restrict to functions in the same package or require `$fast_math` on the callee, and give the compile-time cost of recompiling std.
- `$parallel.off` (14) and channel-communicating `parallel` blocks deadlock when serialised; the "must be correct one item at a time" claim needs a checked obligation or an exception.
- `@work(done)` (07) partial application is not defined in the design or the brief.
- Wrapper functions (03, 04, 11) exist only to host a tag; document the statement-level prefix as the primary form so users do not write them.
- Targets (12): state that a multi-core cap on a target without threads is an error or ignored, and that `read_text` on `wasm32` is out of scope of this design.
- Ambient zone (05, 13, R3) is shorter than a per-call argument but a second statement below the tagged one silently uses the host zone; consider a warning when a tagged statement's following sibling calls the same zone-reading function.
