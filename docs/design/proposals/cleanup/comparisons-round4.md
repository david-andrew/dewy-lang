# Round 4 comparison baselines

These are small idiom outlines, not executed foreign-language programs or package-availability claims. Compare the strongest ordinary idiom for each cleanup case, including a checked adapter when native destruction discards failures. Vectors are O/D/C/S/F. A non-5 dimension is explained on the same source line. Prior comparable resource cases are re-evaluated on their unchanged idioms; no earlier artifact was edited.

Core distinction: Python/TypeScript lexical managers can let disposal errors replace a jump but require disposal opt-in; Go function defer needs explicit error joining; Rust Drop and Swift deinit cannot themselves return a cleanup failure. These are not whole-language rankings. API and driver differences are stated rather than graded as measured speed/usability. Primary references are linked in dogfood-round4.md.

- 01 Python 5/5/5/4/5 — `with open(src, "rb") as i, open(dst, "wb") as o: copyfileobj(i, o)` — S4: each acquisition still opts into with; closing exceptions retain a body exception through context.
- 01 Go 4/4/3/4/5 — `defer func(){ err = errors.Join(err, out.Close()) }(); _, err = io.Copy(out, in)` — O4/D4: named-result mutation and deferred error joining are indirect; C3: include both files and flush/close phases; S4: every acquired resource must register this.
- 01 Rust 4/4/3/4/4 — `checked_file_scope(|out| checked_file_scope(|input| copy(input, out)))` — O4/D4: checked-close scope is a custom adapter, not File::drop; C3: the adapter must observe close and preserve both errors; S4/F4: stock File drop ignores close errors, so this needs an audited library adapter.
- 01 TypeScript 4/4/4/4/5 — `await using input = await openInput(src); await using output = await openOutput(dst); await copy(input, output)` — O4/D4: async disposal is a separate protocol; C4: async declarations and adapter; S4: using must be selected at acquisition; SuppressedError retains both failures.
- 01 Swift 4/4/3/4/5 — `try fileScope(dst) { output in try fileScope(src) { input in try copy(input, output) } }` — O4/D4: throwing completion requires a fileScope helper; C3: a raw defer cannot simply throw its cleanup failure outward; S4: caller chooses the helper.
- 02 Python 5/5/5/4/5 — `with socket.create_connection(address) as sock: send_and_read(sock)` — S4: context opt-in is required; early return is otherwise straightforward.
- 02 Go 5/5/5/4/5 — `conn, err := net.Dial(...); if err != nil { return err }; defer conn.Close()` — S4: defer registration is manual; local release is the requirement, not a successful peer protocol.
- 02 Rust 5/5/5/5/5 — `let mut stream = TcpStream::connect(address)?; send_and_read(&mut stream)?` — RAII covers local socket release, including early returns; this case needs no fallible graceful-close promise.
- 02 TypeScript 4/4/4/4/5 — `await using sock = await socketScope(address); await sendAndRead(sock)` — O4/D4: a runtime disposable socket adapter may be needed; C4: adapter/protocol; S4: disposal opt-in.
- 02 Swift 4/4/4/4/5 — `let socket = try Socket(...); defer { socket.close() }; try sendAndRead(socket)` — O4/D4: socket wrapper ownership varies by library; C4: explicit scope cleanup if not owned; S4: registration/adapter choice.
- 03 Python 4/4/3/4/5 — `async with task_group(): await queue_scope(produce, consume)` — O4/D4: queue shutdown is an explicit protocol, not sender-object lifetime; C3: task/cancellation and end-marker/shutdown plumbing; S4: producer must use that protocol.
- 03 Go 5/5/4/3/5 — `go func(){ defer close(ch); produce(ch) }(); for value := range ch { consume(value) }` — C4: cancellation adds select/context plumbing; S3: producer registration is manual, and multiple producers require a single close coordinator.
- 03 Rust 5/5/5/5/5 — `let (tx, rx) = channel(); scope.spawn(move || produce(tx)); for item in rx { consume(item) }` — Owning sender drop naturally terminates a receiver after drain; structured join/cancellation still needs the chosen task runtime.
- 03 TypeScript 4/4/3/4/5 — `await taskGroup(() => queueScope(produce, consume))` — O4/D4: explicit application queue protocol; C3: shutdown/cancellation adapter; S4: ordinary queues do not infer the last producer lifetime.
- 03 Swift 4/4/4/4/5 — `withThrowingTaskGroup { group in group.addTask { defer { continuation.finish() }; produce() }; consume() }` — O4/D4: continuation finish and task termination are distinct; C4: explicit finish/group wiring; S4: remember finish or an owning library sender wrapper.
- 04 Python 5/5/5/4/5 — `with mutex: update_state(); write_log()` — S4: lexical lock context is opt-in, but its extent is clearer than Dewy helper pinning.
- 04 Go 5/5/5/4/5 — `mutex.Lock(); defer mutex.Unlock(); updateState(); writeLog()` — S4: manual unlock registration; a helper is needed if only part of the function is the region.
- 04 Rust 5/5/5/5/5 — `let mut state = mutex.lock()?; update_state(&mut state); write_log()?` — Standard named lock guard lives to the lexical drop scope; poisoned-lock policy belongs to the selected mutex.
- 04 TypeScript 4/4/4/4/5 — `await mutex.runExclusive(async () => { updateState(); await writeLog() })` — O4/D4: library lock callback; C4: callback boundary; S4: lock API choice/discipline, though the region itself is clear.
- 04 Swift 5/5/5/4/5 — `try mutex.withLock { state in updateState(&state); try writeLog() }` — S4: protected access must go through the chosen library lock method; its callback is a region boundary.
- 05 Python 4/4/3/4/5 — `saved = tcgetattr(fd); try: set_raw_with_signals(fd); read_keys(); finally: tcsetattr(fd, saved)` — O4/D4: OS raw vs signal details; C3: manual save/restore and exception composition; S4: manual context or custom manager.
- 05 Go 4/4/3/4/5 — `saved := makeRaw(fd); defer restore(fd, saved); readKeysWithSignals()` — O4/D4: terminal/signal library choice; C3: signal routing plus restore-error return; S4: manually paired state.
- 05 Rust 4/4/3/4/5 — `terminal_scope_with_signals(|terminal| read_keys(terminal))` — O4/D4: nonstandard terminal adapter and raw SIGINT details; C3: restore failures need an explicit completion result; S4: adapter must be selected.
- 05 TypeScript 4/4/3/4/5 — `await terminalScope({signals:true}, async tty => readKeys(tty))` — O4/D4: runtime-specific signal/terminal API; C3: scope and async signal adapter; S4: explicitly chosen scope.
- 05 Swift 4/4/3/4/5 — `try terminalScope(signals: true) { terminal in try readKeys(terminal) }` — O4/D4: POSIX/platform details; C3: throwing restoration and signal plumbing in a helper; S4: helper opt-in.
- 06 Python 5/5/5/4/5 — `with tempfile.TemporaryDirectory() as root: build_archive(root)` — S4: required context opt-in; deletion errors can be raised on exit.
- 06 Go 4/4/3/4/5 — `root, err := os.MkdirTemp(...); defer func(){ err = errors.Join(err, os.RemoveAll(root)) }()` — O4/D4: deferred error joining; C3: manual error/result wiring; S4: registration must be remembered.
- 06 Rust 4/4/4/4/4 — `checked_temp_scope(|dir| build_archive(dir.path()))` — O4/D4: checked removal differs from ordinary RAII tempdir drop; C4: scope/explicit close helper; S4/F4: destructor-only tempdir cleanup is not a removal-error result.
- 06 TypeScript 4/4/4/4/5 — `await using dir = await disposableTempDirectory(); await buildArchive(dir.path)` — O4/D4: disposable directory adapter; C4: async scope protocol; S4: using opt-in.
- 06 Swift 4/4/3/4/5 — `try temporaryDirectoryScope { dir in try buildArchive(dir) }` — O4/D4: library helper rather than core RAII for deletion failure; C3: removal-error handling; S4: opt-in helper.
- 07 Python 4/4/4/4/5 — `async with TaskGroup() as group: task = group.create_task(reader()); task.cancel(); await task` — O4/D4: child cancellation vs parent cancellation needs careful handling; C4: catch expected CancelledError without swallowing the caller cancellation; S4: use socket/task contexts.
- 07 Go 4/4/3/4/5 — `ctx, cancel := context.WithCancel(parent); defer cancel(); go readOwnedSocket(ctx, conn); cancel(); wait()` — O4/D4: socket ownership and context do not automatically coincide; C3: done/error/join coordination; S4: explicit context/release discipline.
- 07 Rust 4/4/4/4/5 — `let task = spawn(async move { read_owned(stream).await }); task.abort(); task.await` — O4/D4: abort/join semantics depend on executor; C4: explicit join/cancellation result handling; S4: ordinary spawn does not itself guarantee structured joining.
- 07 TypeScript 4/4/3/4/5 — `await taskScope(async group => { const t = group.spawn(readOwned); t.abort(); await t.join() })` — O4/D4: AbortSignal alone is not ownership/join; C3: library task scope; S4: choose the structured adapter.
- 07 Swift 4/4/4/4/5 — `await withTaskGroup { group in group.addTask { await readOwnedSocket() }; group.cancelAll() }` — O4/D4: cooperative task cancellation and socket cancellation adapter; C4: asynchronous group result/error handling; S4: adapter must ensure the socket wait observes cancellation.
- 08 Python 4/4/3/4/4 — `with game_asset_scope() as level: game.run(level)` — O4/D4: native resource/fence lifetime is library-specific; C3: explicit contexts for aggregate assets; S4: select the owner scope; F4: actual GPU/audio driver contract is still required.
- 08 Go 4/4/3/4/4 — `level, err := loadLevel(); defer level.Release(); run(level)` — O4/D4: release is separate from backend fence/voice ownership; C3: partial asset failure cleanup; S4: release registration; F4: driver/engine support.
- 08 Rust 5/5/4/5/4 — `let level = load_level()?; run(&mut level)?` — C4: partial engine/driver wrappers and thread-affine assets still need a library; F4: RAII alone does not establish fence or playback lifetime.
- 08 TypeScript 4/4/3/4/4 — `await using level = await loadLevel(); await game.run(level)` — O4/D4: disposable engine assets and voice ownership are library-specific; C3: aggregate adapter; S4: using opt-in; F4: backend contract.
- 08 Swift 4/4/4/4/4 — `try withLevel { level in try game.run(level) }` — O4/D4: ARC is not a GPU fence/voice-lifetime policy; C4: engine scope and thread-affinity adapter; S4: select the correct wrapper; F4: backend contract.
- 09 Python 4/4/3/4/4 — `with NativePattern(pattern) as regex: print(regex.capture_count())` — O4/D4: C ABI/ownership remains an adapter; C3: cffi/ctypes + checked context; S4: unsafe native contract; F4: audited ABI/allocator behavior required.
- 09 Go 4/4/3/4/4 — `pattern, err := compileNative(text); defer pattern.Free(); print(pattern.CaptureCount())` — O4/D4: native lifetime not inferred; C3: cgo wrapper and manual release; S4: manual registration and native contract; F4: audited ABI needed.
- 09 Rust 4/4/4/4/5 — `struct Code(NonNull<pcre2_code>); impl Drop for Code { ... }; let code = compile(text)?` — O4/D4: ABI and ownership wrapper expertise; C4: unsafe adapter; S4: trusted C claims; private fields provide a settled encapsulation route.
- 09 TypeScript 4/4/3/4/4 — `await using regex = await compileNative(pattern); regex.captureCount()` — O4/D4: N-API/Wasm native interface; C3: separate binding/disposal adapter; S4: native trust + using; F4: audited boundary still required.
- 09 Swift 4/4/4/4/5 — `final class Code { private let raw: OpaquePointer; deinit { pcre2_code_free(raw) } }` — O4/D4: C ownership/ABI expertise; C4: native wrapper; S4: unsafe C claims; private fields settle public construction.
- 10 Python 5/5/4/4/5 — `with connection: debit(); credit()` — C4: commit/rollback double failures and uncertain commit need a driver policy; S4: use the transaction context rather than raw executes.
- 10 Go 4/4/3/4/5 — `tx, err := db.BeginTx(ctx, nil); defer rollbackWithErrorJoin(tx, &err); debitCredit(tx); return tx.Commit()` — O4/D4: commit/rollback state and named error mutation; C3: explicit completion and error joining; S4: manual transaction protocol.
- 10 Rust 4/4/4/4/5 — `transaction_scope(|tx| debit_credit(tx))` — O4/D4: driver-specific transaction callback; C4: error composition and commit uncertainty; S4: library protocol selection, even if drop rolls back.
- 10 TypeScript 5/5/4/4/5 — `await database.transaction(async tx => { await debit(tx); await credit(tx) })` — C4: backend-specific uncertain commit and paired rollback errors; S4: use transaction helper rather than independent writes.
- 10 Swift 4/4/4/4/5 — `try database.transaction { transaction in try debitCredit(transaction) }` — O4/D4: transaction/rollback semantics belong to library; C4: paired errors/uncertain commit; S4: choose scoped transaction operation.
- 11 Python 5/5/4/4/5 — `try: scan_rows(rows); finally: print("done")` — C4: explicit try/finally wrapper; S4: an arbitrary omitted done action cannot be inferred.
- 11 Go 5/5/5/4/5 — `defer fmt.Println("done"); scanRows(rows)` — S4: arbitrary forgotten exit action remains undetectable; no language can infer that intention from scanRows.
- 11 Rust 4/4/4/4/5 — `let _done = scopeguard::guard((), |_| println!("done")); scan_rows(rows)?` — O4/D4: scopeguard library and binding semantics; C4: guard adapter; S4: explicit registration; Rust println can panic, so choose a non-panicking logging action for true parity.
- 11 TypeScript 5/5/4/4/5 — `try { await scanRows(rows); } finally { console.log("done"); }` — C4: explicit try/finally structure; S4: arbitrary missing action not detectable.
- 11 Swift 5/5/5/4/5 — `defer { print("done") }; try scanRows(rows)` — S4: arbitrary missing action is undetectable; scope timing is otherwise direct.
- 12 Python 4/4/4/4/5 — `with ExitStack() as stack: outputs = [stack.enter_context(open(path, "wb")) for path in paths]; write_all(outputs)` — O4/D4: ExitStack for dynamic owner collections; C4: register each opened file; S4: use the contexts. Closing exceptions preserve pending exception context.
- 12 Go 4/4/3/4/5 — `defer func(){ err = errors.Join(err, closeAll(outputs)) }(); openAndWriteAll()` — O4/D4: prefix ownership and named-error join; C3: explicit all-element cleanup/error collection; S4: manual registration. closeAll must attempt every initialized output.
- 12 Rust 4/4/3/4/4 — `let outputs = open_all()?; let body = write_all(&outputs); combine(body, checked_close_all(outputs))` — O4/D4: Vec owns files but Drop ignores their close errors; C3: explicit aggregate finish and pairing; S4: choose checked native adapters; F4: Vec<File> destruction alone cannot supply fallible completion results.
- 12 TypeScript 4/4/4/4/5 — `await using stack = new AsyncDisposableStack(); const outputs = await openAll(stack); await writeAll(outputs)` — O4/D4: dynamic disposal stack; C4: adopt each output; S4: caller chooses the owning stack. Disposer failures can be retained by SuppressedError.
- 12 Swift 4/4/3/4/4 — `try checkedOutputScope(paths) { outputs in try writeAll(outputs) }` — O4/D4: file close errors need a checked adapter rather than ARC; C3: aggregate finish/error plumbing; S4: select the helper; F4: ordinary array deinit cannot report close failures.
- 13 Python 4/4/4/4/5 — `with resource: work()` — O4/D4: fallible completion is a context-manager protocol; C4: write/use the manager; S4: caller must choose with. __del__ is not the checked completion route.
- 13 Go 4/4/3/4/5 — `defer func(){ err = errors.Join(err, resource.Close()) }()` — O4/D4: deferred mutation of a named error result; C3: phase and pair plumbing; S4: every owner must register the checked close.
- 13 Rust 4/4/4/4/4 — `let result = work(); let finished = resource.finish(); combine(result, finished)` — O4/D4: fallible completion is outside Drop; C4: explicit finish/combine; S4: caller selects the checked route; F4: Drop itself cannot forward the failure, so this needs a checked adapter/discipline.
- 13 TypeScript 4/4/4/4/5 — `using resource = makeDisposable(); work()` — O4/D4: dispose protocol and SuppressedError; C4: reusable adapter; S4: caller chooses using. A throwing disposer can replace normal exit and retain a previous exception.
- 13 Swift 4/4/3/4/4 — `let result = Result { try work() }; try checkedFinish(resource, result)` — O4/D4: throwing completion is separate from deinit; C3: explicit outcome helper; S4: caller chooses it; F4: deinit alone cannot make an ordinary caller return the cleanup error.
- 14 Python 4/4/3/3/4 — `async with TaskGroup(): produce_then_shutdown(queue); consume(queue)` — O4/D4: a coordinator must know all producers are done; C3: shutdown/cancellation coordination; S3: a missing shutdown can hang; F4: ordinary shared queue handles do not identify the last producer automatically.
- 14 Go 4/4/3/3/4 — `go func(){ producers.Wait(); close(ch) }(); for v := range ch { consume(v) }` — O4/D4: close belongs to exactly one coordinator; C3: producer-count/error coordination; S3: missing/early/double close can hang or fail; F4: ordinary channel handles are not owned sending endpoints.
- 14 Rust 4/4/4/4/5 — `spawn_with(tx.clone()); spawn_with(tx); for value in rx { consume(value) }` — O4/D4: implicit endpoint copies and retained roots must be understood; C4: move the final sender or explicitly drop a retained root; S4: a forgotten root clone can keep receive open. Last sender drop otherwise supplies closure.
- 14 TypeScript 4/4/3/3/4 — `await runProducersThenClose(queue); await consume(queue)` — O4/D4: queue-library shutdown policy; C3: coordinator/cancel/join wiring; S3: missed close can hang; F4: generic shared queues do not infer last sending interest.
- 14 Swift 4/4/3/3/4 — `await withTaskGroup { producers in ... }; continuation.finish()` — O4/D4: producer completion and continuation finish are distinct; C3: coordinator/error/cancellation wiring; S3: missing finish strands consumption; F4: completion ownership needs a library adapter.
- 15 Python 5/5/5/4/5 — `for path in paths: with open(path) as f: ...; break_or_continue` — S4: choose the context at acquisition. __exit__ failure naturally supersedes a loop jump while exception context retains a pending failure.
- 15 Go 4/4/3/4/4 — `for each path: iterationHelper(path) returns continue/break/error outcome` — O4/D4: Go defer is function-scoped, not the loop body; C3: helper/control outcome or duplicated close on jumps; S4: register checked cleanup; F4: preserving the outer jump and fallible cleanup needs extra control plumbing.
- 15 Rust 4/4/4/4/4 — `for path in paths { let file = checked_open(path)?; finish_before_jump(file)?; ... }` — O4/D4: Drop does not return close errors; C4: explicit finish before every crossing jump or a checked iteration helper; S4: choose the checked route; F4: automatic RAII alone does not supply this failure propagation.
- 15 TypeScript 5/5/4/4/5 — `for (const path of paths) { await using f = await openDisposable(path); ... }` — C4: async disposal adapter; S4: explicit using at acquisition. Disposal errors can supersede break/continue without a callback boundary.
- 15 Swift 4/4/3/4/4 — `for path in paths { try checkedIteration(path) }` — O4/D4: lexical defer cannot simply throw outward; C3: helper/control outcome or explicit close; S4: choose checked cleanup; F4: preserving arbitrary outer jumps needs extra structure.
- 16 Python 4/4/3/4/4 — `guard_new_result_until_old_context_exit_succeeds()` — O4/D4: a returned new owner must remain protected when another __exit__ fails; C3: transfer-capable ExitStack/custom guard; S4: explicit guard; F4: a plain unregistered returned file can lose its own close error during abandoned return cleanup.
- 16 Go 4/4/3/4/4 — `defer failedReturnCleanup(&result, &err); finishOldOwnerBeforeReturn()` — O4/D4: named owning result plus close failure can cancel handoff; C3: explicit result-disposal/error joining; S4: manual guard registration; F4: language return/defer alone does not infer the ownership handoff protocol.
- 16 Rust 4/4/3/4/4 — `hold_new_owner(); finish_old()?; transfer_new_owner()` — O4/D4: distinguish returned ownership from local guards; C3: retain/finish both fallible owners with pair handling; S4: choose checked adapters; F4: ordinary Drop of the abandoned new File ignores its close error.
- 16 TypeScript 4/4/4/4/5 — `await using pending = transferGuard(newOwner); await finishOld(); return pending.take()` — O4/D4: explicit transfer guard/disposal protocol; C4: guard adapter; S4: caller uses it. SuppressedError can retain a pending finish failure when pending result disposal fails.
- 16 Swift 4/4/3/4/4 — `try owningResultGuard { pending in try finishOld(); return pending.transfer() }` — O4/D4: explicit checked ownership transfer; C3: adapter rather than ARC deinit; S4: caller chooses it; F4: deinit alone cannot report both fallible releases.
- 17 Python 4/3/3/4/5 — `fresh = open_new(); try: close_old(); finally: destination = fresh` — O4: old close failure occurs after a successful acquisition; D3/C3: publish-in-finally and guard fresh on every path need careful code; S4: explicit helper/contexts. A robust helper can keep destination initialized and preserve both errors.
- 17 Go 4/3/3/4/5 — `fresh := openNew(); old := destination; destination = fresh; return old.Close()` — O4: failure does not mean unchanged destination; D3/C3: partial acquisition, publication and error joining are explicit; S4: manual helper discipline.
- 17 Rust 4/4/3/4/4 — `checked_replace(&mut destination, fresh) returns old-close error after publication` — O4/D4: a failed operation may already change destination; C3: checked-close native wrapper; S4: caller selects it; F4: ordinary mem::replace plus File::drop loses close failures.
- 17 TypeScript 4/3/3/4/5 — `await resourceSlot.replace(newResource)` — O4: mutation can commit before disposal failure; D3/C3: mutable resource slot needed because using bindings are not a generic reassignment-finalization protocol; S4: use the owning container adapter.
- 17 Swift 4/3/3/4/4 — `try checkedReplace(&destination, fresh)` — O4: failure can leave the new value installed; D3/C3: explicit checked replacement rather than plain ARC assignment; S4: library protocol choice; F4: deinit alone cannot forward a close error.
