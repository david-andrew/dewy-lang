# Retire the live bootstrap twins with a pinned source seed

**Proposed decision.** Freeze the inputs that build the first Dewy-capable compiler, generation 2 (G2), in one versioned source archive. Build it from C on Linux x86-64. Let G2 read the current compiler and library directly. Cache the resulting seed by digest. Remove the 600 paired Jo files from the working compiler once the new path and their replacement tests pass. Keep the Jo compatibility reader for the live Jo sources and libraries.

On the planning base `e931c73de`, the proposed archive occupied **2.77 MB**. A clean rebuild from it produced the same current compiler as the existing bootstrap, with the twins absent. A generated-C seed also produced the same bytes, at **16.11 MB** compressed and about four times the cold build instructions. An older G2 built from source proved an important detail of the update procedure. It took **three** builds of current source to establish a fixed point.

This round owns this proposal. The experiments used scratch copies. Compiler edits, a release seed, language changes and changes to the work queue are outside its three-hour budget. Milestone 1 concerns who executes the compiler. Milestone 3 concerns what a fresh checkout must trust and build. Their acceptance tests are different. ## Finish the execution cutover

The five files named in the roadmap have **24** top-level function definitions at this revision. The seven in its optimizer count comprise five decode/rewrite helpers and two register resets. The eighth, `opt_bind_addresses`, takes addresses. One of the seven, `cse_arity`, now has only a test caller. Counting top-level Jo function headers across the compiler, excluding the 600 same-stem twins and `dewy_reader_seed.jo`, gives **100 definitions in 22 files**, including overloads. Many forward straight into Dewy. Two important exceptions are the actual `compile` and `main` bodies in `main.jo`.

### The six declaration collectors

**Replace** all six by changing the output parameter through the whole call chain. Jo currently turns a mutable array *variable* into a pointer to its header using `&out`. The callee appends and may replace its backing allocation. Dewy's element pointer `.ptr` cannot stand in for that header. The collector bodies already live in Dewy. Use an ordinary mutable `@out:array<int64>` parameter in `checker_call_queries`, its internal forwarding helpers, the `CheckerCollectHost.rational` function type and `collect_rational`. Update standalone Jo callers and, while the old bootstrap is active, their twins. There is no need for a general address-of operator here.

| Remove from | Function | Direct destination and contract to retain |
|---|---|---|
| expr.jo | `call_collect_module` | `collect_module` appends visible declarations of the requested module and its uses. |
| expr.jo | `call_collect_named` | `collect_named` preserves shadowing, prepopulated output and the name-stamp cache, including replay of hidden declarations. |
| expr.jo | `call_collect_fns` | `collect_fns` searches the current module, prelude and applicable rational family. |
| check.jo | `warning_collect_in` | `collect_in` preserves the caller's hide mode, order and duplicate suppression. |
| check.jo | `values_collect_fns` | Same `collect_fns` entry used by expression checking. |
| check.jo | `values_collect_module` | Same `collect_module` entry, including successive appends from method modules. |

There are 58 static call expressions for these adapters in compiler Dewy source. Exercise an empty, prefilled and shared destination, growth during an append, lazy module discovery, and cached and uncached shadowing. Compare the declaration sequence and hidden-name side effects. ### Optimizer, state and driver

| opt.jo function | Recommendation and condition |
|---|---|
| `o_pure` | **Replace** the Op-only query with the purity bit at the caller's instruction. Reuse `oc_tag`/`oc_pure` where the instruction and the bound decode table are already available. |
| `o_defines` | **Replace** similarly using the defines bit. Supply the initialized `o_decode` table to sibling passes. SRA runs before `optimize` sets the rewrite workspace's `opt_decode`. |
| `kills_memory` | **Replace** with bit 4 at those instruction sites in inlining/copy forwarding. Avoid converting an opcode to text or adding a function-pointer call. |
| `cse_arity` | **Replace** the test-only Jo oracle with an independent expected-arity fixture for every opcode and both index modes, including indexed load = 2. Production already has `ow_arity`. |
| `o_rewrite` | **Move** the operand-mask operation to Dewy and share it with `ow_rewrite`. The loop copier rewrites a local instruction and can just have grown `ir.args`. Pass the mutable instruction and its *current* argument storage, including for span operands. The rewrite pass's cached argument pointer has a shorter validity window. |
| `o_resize` | **Move** the bulk reset when the loop emits the same per-register work. Preserve capacity reuse, doubled fact tables, pointer refresh and all sentinels. The earlier extra sign extension per register measured +0.013% on a flagship. Inspect the narrowing of the replacement index before retrying. |
| `o_resize_one` | **Replace** with the existing `ow_resize_one` after checking preconditions for SRA and loop versioning. Refresh `o_regs` after growth and reset even a reused slot. |
| `opt_bind_addresses` | **Keep in Jo** as a storage bridge for the current IR, two instruction slots and operand tuple. Retire it when the owner passes these by place or owns addressable stable storage in Dewy. Bind after initialization and on entry as required by the nested SRA retry. |

The opcode ABI has 107 tags. `oc_tag` reads the first 32-bit field of an addressable `Ins`. Use a borrowed instruction only where its owner remains valid. Keep a value-only Jo query temporarily at a site where constructing or copying an instruction would add work. Test the actual bit and operand behavior across all tags and exercise SRA before the first rewrite. [Decode table and pass order](../../../../compiler/opt_core.dewy) · [Instruction access](../../../../compiler/opt_cleanup.dewy) · [Sibling loop copier](../../../../compiler/loops_emit.dewy)

**Keep the shared Jo storage through milestone 1.** The AST has sentinel `nodes[0]` and a separate child-list arena. The checker has type and argument tables, functions, symbols and module state. Facts and exact have per-compilation caches and per-function scratch. The backend shares the current `IrFn` and register and operand views. Dewy already owns record layouts and some storage, including the optimizer register workspace. Preserve one mutable owner per table, IDs, initialization order, reset lifetime and copy-on-write. A pointer to a stable array header survives element-buffer growth. An element pointer must be reacquired after a grow or reentrant call. The 71 top-level `*_binding` assignments in `host_binds.jo` illustrate the ordering constraint in the import cycle.

Move storage later, one owner with its writers, when direct imported Dewy globals or explicit mutable parameters can replace each address binding. Begin with a self-contained cache. Test retained snapshots, growth, two compiles in one process and worker isolation before moving a shared arena. Keep late host construction after its dependencies. A single record wrapping the entire compiler would change alias information throughout the hot paths. [Bindings](../../../../compiler/host_binds.jo) · [Workspace](../../../../compiler/opt_workspace.dewy)

**Milestone 1 exit.** Of the other 76 headers, 59 belong to `ast`, `types`, `nd_contracts`, `util` and `directives` and forward access or operations to Dewy. Remove forwarding names as their callers move. Classify the other 17 at review. Move the substantial `main.jo:compile` pipeline and `main` dispatch into the existing driver leaves, preserving target setup, demand-driven lowering, the prelude-global fixed point, emission and exit behavior. Keep a thin entry stub if it is still needed. Move the member-body check/expand policy and the formatter's save/restore orchestration. Isolate low-level operations such as formatter nonlocal exit, `par.jo:pr`'s unaligned word read and watch signal address binding. An automated inventory should flag new live Jo bodies and require an explicit reason for each retained ABI, platform or storage bridge. A planner, optimizer walk or compiler pipeline still running in Jo keeps the milestone open.

## What boots today

1. The Python builder copies `compiler/`, `lib/`, `stage0/`, `bootstrap/` and `LICENSE` to a build directory. It derives `FROZEN_TWINS` from every `compiler/*.dewy` basename and requires the corresponding `.jo` at module import time. In the temporary compiler, it overlays five bootstrap modules and rewrites exact Jo `use 'X.dewy'` lines to `use 'X.jo'`.
2. **C → G1, `core-bootstrap`.** Make compiles `util.c`, `lex.c`, `parse.c`, `types.c`, `check.c`, `expr.c`, `gen.c` and `main.c` with two headers. The resulting `sloppy0` opens the sorted `lib/core/*.jo` prelude and `compiler/main.jo`, then loads imports recursively. Quoted paths resolve relative to the importer. Bare names try the local directory and then the library. It emits x86-64 assembly and invokes GCC to assemble/link a static Linux executable.
3. The five overlays are `frontend.jo`, `source_frontend.jo`, `dewy_fmt.jo`, `formatter_frontend.jo` and `dewy_context.jo`. They supply the Jo declarations reader, no-op lazy body forcing, formatting stubs and a small parser context. A scratch trace of successful source opens in the actual C executable's assembly-only run found **661 compiler Jo files and 10 core Jo files**. The core stems were array, fmt, macos, map, math, os, overflow, rt, str and windows. Of the 661, 572 had twin basenames, including the two *overlaid* frontend twins. G1's construction did not open `dewy_reader_seed.jo`.
4. **G1 → G2, `dewy-core-bootstrap`.** Restore the compiler's five real modules, still pointing their Dewy imports at twins. G1 reads Jo. This time the full reader enters the graph via `dewy_reader.jo` and its `dewy_reader_seed.jo` implementation. G2 understands both Dewy and Jo.
5. **G2 → G3, `dewy-core`.** Restore original imports, point `DEWY_CORE_LIB` at the staged live library and compile `compiler/main.jo`. The running G3 uses the Dewy leaves. **G3 → G4** with `--fixed-point` moves the executable aside, rebuilds at the identical path and compares every byte. Source paths and cwd matter. Today's separate `--seed` route tries the live graph first and, on build failure, may build an interim compiler through twins. Deletion must replace that fallback and the import-time inventory.

The landing guard examines the whole base-to-head range for changed leaves, a changed twin (or reader seed), and a named differential test. `call_forward` is an explicit bootstrap stub. Separate tests check inventory, import direction, exported names and enum order. A changed-path check alone cannot establish that two compilers agree. ## Three ways to pin the first compiler

Sizes below are decimal MB. Build cost is **billions of retired user instructions** on the i7-6700 desktop, GNU/Linux x86-64, GCC 16.2.1. The repo's `count_instructions.c` counted each command and its children, with equal time enabled/running, cold C objects, compiler cache disabled and one emission worker. Totals exclude Python staging, compression and hashing unless specified. The existing route cost **27.79 G** for C compilation, **60.26 G** for C seed → G1 including assembly/link, **55.29 G** for G1 → G2, **14.14 G** for G2 → G3 and **13.50 G** for G3 → G4, or **170.97 G** through the fixed point. These are build-work measurements. Elapsed time depends on host and toolchain.

| Route | Fresh checkout and size | Cold build through a verified current compiler | Guard after cutover |
|---|---|---|---|
| **A. Generated C snapshot** | Compile a checked-in snapshot with its runtime and startup assembly, then use that executable on live sources. Pilot source **72.53 MB**, **16.11 MB** as tar/gzip. GCC-built host **35.34 MB**. | **603.77 G** for serial GCC `-O0` compilation/link, **69.77 G** for its current-source build, **13.50 G** for verification, about **687 G**. Generating the snapshot adds **19.76 G** for host IR and **89.62 G** for translation only on refresh. | Check snapshot digest and reproducible regeneration at its pinned revision on refresh. Regular landings build current sources with that seed and check convergence and behavior. |
| **B. Pinned native G2 with a C source recipe** | Ship the immutable recipe and source capsule in the clone. Extract and build G2 offline, or use a digest-verified, host-specific cache. Measured capsule **2.77 MB** compressed / **10.24 MB** unpacked before the small build script. G2 **19.09 MB**, **6.39 MB** gzip if distributed. | About **171 G** from C at the same revision. A ready G2 needs **27.63 G** through verification. With the older tested pin, three live builds cost **41.07 G** after producing G2. | Verify the pin's source and recipe, a clean G2 rebuild and the live fixed point. Regular leaves carry behavior tests. The frozen archive never changes alongside an ordinary leaf. |
| **C. Restricted Dewy reader in C** | Build a C reader/lowerer for a specified bootstrap dialect. Feed it a *pinned bridge written in that dialect* which can read normal Dewy and Jo, then build live sources. An alternative is to restrict the compiler's entire transitive input to the subset. | Unimplemented. A planning model charges 28 G to build the C tool, 60 G to build the bridge and 28 G for two live builds, about **116 G**. Another intermediate compiler of G1 → G2 size adds about 55 G. Each term is a proxy from today’s chain. | Check the pinned bridge's closure against an executable subset spec, require the C reader to reject everything outside it, then differential semantics, bootstrap and fixed point. |

**A is feasible today on the reference host.** The compiler emits versioned scalar `--host-ir`. A scratch version of the retired translator emitted 7,942 functions in 157 C translation units including the runtime, plus a header and `start.S`. This was a two-step export. Direct self-emission of C would add an emitter to maintain. The translator from the parent of `8dc562838` needs checked and overflowing arithmetic, 32-bit rotate and the byte-scan operations for this IR. The pilot implemented the indentation bits of `findb`, separated `findbyte` inversion from AVX2 width, and handled CPU feature intrinsic 9. GCC used `-fno-strict-aliasing -fno-strict-overflow -ffp-contract=off` and disabled null-dereference optimizations. Linux syscalls, x86 startup and setjmp, function-pointer ABIs and unsupported native threads limit portability. Unknown instructions must fail the exporter. Canonicalize generator inputs/paths and pin the translator, runtime and flags. Keep the old source-build route available to regenerate and independently compare the first snapshot. [Compiler host-IR experiment and translator provenance](../compile-speed/codegen-gap-round1.md#scope-and-method)

**B can be rebuilt using the existing toolchain.** The pilot packed all 696 historical `compiler/*.jo` files with imports already rewritten, the five rewritten overlays, stage0, the historical library with its Dewy files omitted, and the license. Extract privately, overlay the five stubs, run Make and `sloppy0`, restore the five full frozen modules, then build G2. At that boundary switch to the *current* compiler tree and *current* library. This route keeps historical Jo representations inside one immutable artifact. It removes the obligation to maintain a Jo version of any live change. A less specialized archive of the original compiler, library, stage0, bootstrap, builder and license was **4.37 MB** (`git archive -9`) and offers a straightforward independent reconstruction.

For both A and B the experiment removed all 600 live twins (**6,251,543 bytes**), the separate reader seed (**420,110 bytes**), and the stage0 and bootstrap directories from the *live input*. Each seed rebuilt the control's **17,393,088-byte** executable and reproduced it on the next self-build at the same paths. On a second extraction of B at the same build root, GCC- and Clang-built stage0 produced **identical G2 bytes**. G1 differed in six bytes of the temporary assembler-object basename in its ELF string table. G2 is a sounder digest boundary. Fixed-point equality is useful separately from reproducing the trusted pin from C.

The older-pin trial used `8eec1e9fd`, 76 commits before the planning base. Its G2 built the twin-free tree in **14.08 G**. That executable had the expected size but a different hash. Its rebuild and the next rebuild both matched the control, **13.50 G** each. A fresh-clone contract must allow this extra generation, verify adjacent *current-source* builds, and stop with both files and the first differing offset if the allowed generations fail to converge.

**C needs a size and language bound before implementation.** For scale, today's stage0 including Makefile is 303 kB / 8,052 lines, the frozen Jo reader alone is 420 kB, and the 600 live Dewy leaves occupy 7.93 MB. Of those leaves 469 mention `$unsafe` and 526 mention an overflow policy. A transitive feature inventory would have to resolve imports and instantiated types as well. For a restricted bridge, provision roughly **0.1–0.5 MB of additional C** and **1–8 MB of bridge source** as planning estimates. Measure the transitive bridge input before adopting either bound. A subset covering the live graph would also have to support cyclic imports, mutable places, literals/union layout, generic instantiation, library loading and current Jo inputs. A smaller bridge moves that complexity into the bridge itself. It risks creating a second evolving frontend. A first pilot should compile a mixed recursive module, its library and an actual reader entry through both paths, and publish its unsupported forms and size before funding a full bootstrap.

## Land route B in stages

Allow **10–18 engineer-days** for the five stages below, separate from the milestone 1 ports. The trials covered Linux x86-64. Start by preserving the pin while both paths work. Make the deletion after milestone 1 review. Test migration and future seed compatibility account for most of the uncertainty.

| Stage | Deliverable and automated acceptance gate | Effort |
|---|---|---:|
| 1. Pin a green revision | Generate a sorted, deterministic archive from the named Git revision. Pin member hashes, recipe/version, license, host/toolchain, flags and the canonical build root for byte comparisons. Recreate the archive twice from clean trees, rebuild G2 from C without a binary or network, and verify its reference SHA-256. Reject a corrupted archive or cache. | 1–2 days |
| 2. Run both bootstrap paths | Add the archive route beside today's independent builder. Use separate roots for the seed and live inputs and a common canonical path for comparing final binaries. Exercise an empty cache, a valid cached G2, the older-seed three-build case and a divergent generation. Preserve the public build/test entry points, source identity and build provenance. | 2–3 days |
| 3. Retire leaf-by-leaf comparison | Migrate the shared differential harnesses first. There are 616 `test_selfhost_*.py` files to classify, including behavioral tests. Keep expected values, failure diagnostics, ABI fixtures, mutation, editor protocols and both build modes. For equality-only cases, retain independent oracles or expected fixtures captured and checked before deletion. Exercise a deliberate opcode/operand error to verify the replacement oracle. Run the full old and new test paths through the transition. | 4–8 days, revise after the first harness family |
| 4. Switch and delete | From a shallow, offline checkout without any live twins or a preinstalled Dewy binary, build through the pin, run the full suite and require a fixed point. Compare the old and new paths on the *same* source at matched paths. Run `same_output` for examples/ladder across its six modes, and compile the seven flagship inputs explicitly. Require identical outputs on successful cases and asserted status/diagnostics for rejection cases. Run the release host matrix for Linux arm64, macOS arm64 and Windows x64 using the Linux-built compiler. | 2–3 days |
| 5. Exercise a pin update | Before current compiler sources begin to require a feature the old seed cannot read, have that seed build a bridge revision that implements the feature using old syntax. Keep the previous pin usable for rollback. | 1–2 days for the first drill |

Stage 4 removes the dynamic twin inventory, import rewriting and interim-twin fallback from the live builder, plus the five overlays and reader seed outside the archive. Adjust `tools/core.py` cache inputs, landing/nightly test selection, `twin_guard`, release packaging and the twin-only equivalent-source speed control together. Preserve the ordinary instruction panel and raw self-build/source-cost gates. The new landing guard checks seed compatibility, live-only inputs and behavioral coverage. Rebuilding the reference G2 from its archived C route stays an independent batch/CI gate. Keep the old path on the prior revision until both routes and the release jobs pass. The cold-clone and fixed-point gates should run through both `python3 -m tools.core --bootstrap test` and the standalone builder with `--bootstrap --fixed-point`. A download or a Git tag alone leaves a shallow offline clone unable to recover its seed. Ship the small source payload in the checkout. Cache binaries only under their host, recipe and source digest. Pin source/build paths or provide a canonical mount in reproducibility CI, since the compiler embeds paths. Allow ordinary local builds in user-selected directories to verify their own fixed point. If bridge snapshots start accumulating, measure their total size and build cost against A at the next checkpoint.
