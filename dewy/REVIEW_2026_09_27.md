# Review of work since 4a3ce3cb

Reviewed `4a3ce3cb..ae09f7d5` and the uncommitted copy-policy/documentation
changes present on September 27. The committed range spans 196 files and
about 20,600 added lines; much of the volume is the four object writers and
bytecode support. This is a code and design review with targeted execution,
not a claim that the whole compiler has been verified.

The direction is mostly sound. Keep the borrowing/move improvements, record
family representation, conditional component ownership, region runtime,
prelude reuse, and direct binary path. They address measured costs without
requiring a different language. The changes to scalar transmutes, range
ends, integer conversions, and condition lowering are appropriate bug fixes.
The latter preserves µDewy's specified condition-only short circuiting.
The hosted compiler still uses only the standard library at runtime.

## Correctness repairs made during review

- **Aggregate equality must preserve operand evaluation order.** In both
  compilers, `xs =? change(@xs)` saved the address of `xs`, then compared
  against its mutated contents. A one-element example returned true after
  changing `[1]` to `[2]`. Both lowerers now use borrowing/effect evidence to
  snapshot a left operand when evaluating the right can change its value.
  Read-only comparisons retain the borrowing path. Snapshots are reported
  to the copy policy and released after use.
- **Nominal identity participates even without added fields.** Hosted
  `same=(a:Root b:Root):>bool=>a =? b` returned true for distinct children
  `A[1]` and `B[1]` when neither child added fields. It now checks the brand
  whenever the layout carries one, matching native behavior.
- **Unsupported nested equality must stay unsupported.** Hosted record and
  array helpers could accept nested dictionaries/sets, including comparing
  dictionary handles. They now diagnose the pending operation, as native
  does. This does not choose a new dictionary/set equality design.
- **Place writebacks must retain temporary cleanup.** Hosted calls returning
  arrays/strings skipped statement-temporary tracking when they also had
  place arguments. Equality tests exposed leaked array results. Tracking
  now resumes after evaluating the call and writing back its places.
- **A rebound string parameter is not the original caller-owned string.**
  The progress log already recorded a hosted read-after-region-release
  problem. Clearing released storage reproduced it in
  `native_string_lifetimes.dewy`. Result sizing and storage classification
  treated a reassigned parameter as the original input; place assignments
  could also publish a callee's region-backed string. Transitive parameter
  effects now invalidate that assumption, unknown-sized results use the
  caller's result region, and place stores acquire escaping storage before
  the callee releases its region. Regression tests clear released chunks,
  rather than depending on an allocator happening to reuse one.

The fixes preserve the recorded language decisions. The full native
retention budget is still not a hosted guarantee: the existing hosted
string-lifetime test explicitly checks values separately from that budget.
These repairs do not claim to finish hosted string ownership or prove that
all region lifetimes are correct.

## Copying and `$explicit_copies`

There are three different questions here:

1. **Meaning:** `let b=a` gives `b` an independent value. Later mutation of
   `a` must not change `b`. This remains ordinary Dewy, without a directive.
2. **Implementation:** independence can come from a borrow, a move, copying
   storage, or provisional copy-on-write. Immutable string bytes can remain
   shared indefinitely; mutable array sharing can defer work until a write.
3. **Policy:** `$explicit_copies` opts a module into rejecting an implicit
   copy whose cost is not proven bounded. `.copy()` explicitly accepts an
   independent copy. This is a performance discipline, not a requirement to
   spell every assignment differently or an aliasing mode.

The newly recorded decision to exclude ordinary immutable string sharing is
reasonable. It need not exempt mutable array snapshots: their future detach
can still cost an amount proportional to their contents. The longer-term
question about COW latency remains open, as requested.

The uncommitted implementation is incomplete in two specific ways:

- `copy_policy.runtime_sized` in both compilers still treats strings inside
  records, fixed arrays and unions as unbounded copied payloads. The lowering
  patch only filters notes whose *outer kind* is `string`. A fixed record
  containing a string and a number can therefore still require `.copy()`
  because of the string, even though the native implementation shares its
  immutable bytes. The policy needs to distinguish sharing string bytes from
  recursively copying
  mutable storage, including at allocator boundaries and with copy hooks.
- Hosted placement copies are marked `runtime_sized=False` to exempt them
  from the source policy. Some really do copy runtime-sized bytes. Keep their
  physical-cost classification accurate and give policy exemptions their
  own field/category. Otherwise future analysis can mistake an exemption
  for a proof of bounded work.

Do not interpret the inventory reduction from 4,111 to 2,631 sites recorded
in the WIP as a runtime improvement: it is primarily reclassification. Track
static sites, actual copied bytes, detachments, allocation traffic and peak
retained storage separately. Keep the WIP until the recursive rule and
hosted/native acceptance checks agree, before expanding strict mode to the
whole compiler. The review leaves that unfinished patch intact.

## Remaining implementation concerns

**Bytecode needs a target identity.** `UBC1` stores already-folded constants
but its header has no target. `Stream.play` accepts a different backend.
Recording `main => { return SYS_WRITE }` for x86-64 and replaying it on
AArch64 emits `mov x0, #1`; compiling that source for AArch64 emits
`mov x0, #64`. No diagnostic is issued. The current paired pipeline passes
matching targets, so this does not invalidate its fixed-point results.
Before treating `.ubc` as a reusable/public artifact, version the header,
record its target/ABI and reject mismatches in both readers. This remains
unfixed in this review.

**Allocator syntax is ahead of allocator placement.** The hosted compiler
checks `$allocator` and reports lexical escapes, but lowers it as an ordinary
block. Native enters the arena only for blocks that pass `arena_eligible`;
otherwise it uses the enclosing allocator. That is a conservative first
slice allowed by the recorded design, not the complete store-owner rule.
Add the approved fallback diagnostics and finish boundary promotion before
presenting it as a placement guarantee. The arbitrary-expression form and
`$lend` also remain implementation work. Keep the pending designs visible.

**Avoid treating region allocation as a universal performance answer.**
The recorded bounds-checker experiment is useful negative evidence: a
module-sized region increased its working set to about 1.5 GB and did not
improve validation time after runtime tuning. Reusing small heap blocks
already handles churn well. Use arenas at measured lifetime boundaries;
remove unnecessary allocations first. The decision not to land that slower
customer transformation was correct.

**The binary path is a good incremental cut, not the last representation.**
The backend-call recording has strong assembler/reference checks and keeps
the text fallback. Native Dewy still emits tokens and runs a µDewy parser
port, while direct object output still parses the backend's assembly text.
This avoids some serialization and external processes, but preserves parser
and emitter duplication. Keep the implementation, measure its residual
cost, and eventually drive the shared operation stream directly. Do not
add more independently maintained representations just to remove a small
remaining percentage of build time.

## Roadmap recommendations

Keep Phase 1's ordering and the sub-30-second minimum / sub-10-second stretch
targets. Finish ownership correctness and copy-report semantics before a
wider strict-copy rollout. Continue paired acceptance tests; equal bootstrap
binaries can consistently reproduce the same wrong result.

Adjust three statements in the throughput section when revising the roadmap:

- “No analysis may do superlinear work” is too absolute for the intended
  proof system. Require measured scaling, bounded qualifier generation,
  dependency-driven propagation and explicit solver budgets; exhausting a
  budget should yield unknown or a diagnostic, never a guessed proof.
- An arena can remove individual deallocation, but does not make copy proofs
  moot. Two mutable values still need independent meaning, even if both
  survive until process exit. The equality regression is a concrete example.
- Development output speed matters when that output is itself the next
  compiler or a long-running test. Measure frontend time, backend time and
  generated compiler throughput separately, on a fixed corpus and hardware.
  Distinguish a C-built compiler from a compiler emitting C. Do not use a
  lines-per-second comparison with a different language as evidence that a
  particular redesign is necessary or sufficient.

These are corrections to engineering claims, not proposed restrictions on
Dewy's proofs, type-directed juxtaposition, effects or value semantics.

  a freshly hosted-built driver. These include x86-64 and C execution,
