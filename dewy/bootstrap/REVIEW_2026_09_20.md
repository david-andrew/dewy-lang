# Review of the intervening compiler work

Scope: the 70 commits after `7834ca7a` through `814cd47c`, plus the
uncommitted `$explicit_copies` work present when the review started.
This is a source review with targeted execution checks, not a fresh release
certification or a claim that every language case has been tested.

## Direction

Keep the overall direction. Size-class allocation, shared descriptors,
lazy string segmentation, fewer generated helpers/temporaries, and register
allocation remove substantial work without requiring new language semantics.
The direct bootstrap checkpoint is meaningful progress. The semantic ports
largely close existing hosted/native gaps rather than create a competing
language. The recorded September 19 decisions remain the design basis for
ownership work; allocation-failure semantics remain tentative.

| Area | Assessment and next constraint |
| --- | --- |
| Runtime storage and sharing | Useful bootstrap accelerators. Retain value-semantics and detach tests; sharing remains provisional, not the final zero-cost ownership design. |
| Semantic parity | Powers, iteration, quantities, type values, refinements, and prototype checks are useful coverage. Keep independent expected outcomes alongside differential checks. The last recorded corpus result still leaves `nat_types` unresolved. |
| Emission and µDewy backends | Compact emission and shared register allocation are sensible. Preserve eager standalone boolean expressions; conditional emission optimizations must stay in condition contexts. Cross-target assembly tests do not replace execution on those targets. |
| Bootstrap machinery | Two/three-generation selection and a verified direct route are useful. A fixed point is a reproducibility check, not proof of correct source semantics. |
| Borrowing and moves | Continue, but require alias/lifetime evidence at value boundaries. Distinct binding ids and read-only parameter summaries alone are insufficient. Two failures below demonstrate this. |
| Copy reporting and strict modules | Useful visibility, incomplete as an acceptance policy. Complete coverage, source attribution, explicit remedies, and hosted/native strict-mode parity before enabling it throughout the compiler. |
| Tokenization | Fused-grapheme fixes improve coverage but reveal a representation mismatch. Consider a scalar cursor with source-span mapping instead of accumulating quote/escape exceptions. User-visible strings can retain grapheme semantics. |

## Corrections made

1. **Restore a field-assignment snapshot before releasing old storage.**
   The `16fb3fd8` fast path treated different root binding ids as disjoint
   storage. A place parameter can alias a global record; `target.inner =
   global.inner` then released the source before retaining it. The regression
   lost its nested array and returned 2 instead of 42. Remove this assignment
   shortcut until disjointness and evaluation-order proofs exist. Keep the
   record/cell literal optimization, which has no old field to release.

2. **Keep raw-exposed records across call value boundaries.** The relaxed
   record argument rule from `ec520478` relied on parameter effects, but a
   callee can write the caller's record through a previously exposed raw
   pointer. The regression read 99 through a value argument that should still
   contain 42. Both lowerings now preserve that snapshot. Root discovery
   also follows casts, dictionary reads, and analysis wrappers when recording
   exposure; a wrapper must not erase the storage provenance.

3. **Attribute imported function copy notes to their defining file.** Hosted
   lowering used the entry source for all function spans. Besides misleading
   reports, this bypassed the in-progress strict directive in imported
   functions. Lowering now scopes source attribution to each function,
   including parameter lowering, and restores it afterward. Imported
   top-level initialization and complete report coverage still deserve their
   own audit before strict-copy mode becomes a general guarantee.

4. **Use exponentiation by squaring for native constant powers.** The first
   port multiplied once per exponent unit, so even `1^1000000000000` took
   exponent-sized work. The replacement takes logarithmically many
   multiplications (plus unavoidable exact-result growth). Regression cases
   include zero, negative one, positive/negative exponents, and the existing
   rational and quantity cases.

5. **Recognize raw/template prefixes before a fused opening quote.**
   `r"́a"` was accepted by the hosted compiler but rejected natively as an
   undefined `r`. Inspect the prefix separately and let the existing quote
   probe handle the fused grapheme. The regression also verifies that raw
   backslash text remains raw. This is a bounded fix, not completion of the
   broader scalar-tokenization follow-up.

6. **Reject incomplete copy reports.** `tools/copy_report.py` returned success
   if a failing compiler printed any copy notes first. A partial inventory
   cannot establish a copy budget. Preserve the failure status and output;
   also parse quoted compiler command paths correctly.

7. **Require intrinsic identity for repeatable prototype-check operands.**
   Both compilers treated calls named `__add__`, etc. as effect-free even
   when they referred to user functions. Such a function may mutate state;
   duplicating it while checking an index is unsound. The purity shortcut
   now requires an unbound intrinsic, and an effectful shadowing function
   cannot be used to synthesize a deferred check. More general name-based
   intrinsic recognition elsewhere deserves a separate audit.

## Roadmap adjustments

The phase order still makes sense. Add a short closure checkpoint before
expanding Phase 1.1: resolve the outstanding corpus expectation, give fixture
runners explicit arguments/expected outcomes, and exercise ownership changes
through a second-generation compiler. A blanket “all native fixtures exit
42” script is not a complete test manifest.

Finish the approved `.copy()` and explicit view remedies before diagnostics
prescribe them. Strict-copy acceptance must not silently depend on which
compiler happens to perform a particular optimization. Keep the unfinished
directive work separate from the corrections above; do not declare it done
because the imported-function regression now passes.

Measure static sites, dynamic bytes/allocations, and elapsed time separately.
The recorded 7,910-to-2,127 copy-site reduction is useful analysis progress,
not a corresponding runtime speedup. A single hot site can dominate thousands
of cold ones. Withdrawing an intrusive sampling profile does not make elapsed
time unimportant or show that useful bottlenecks no longer exist.

Maintain two full-build benchmark rows: C-built executing compiler and
direct-built executing compiler, including the provenance of µDewy. The
former is around 20 s; the latter around 45 s. The direct route still misses
the under-30-second target; under 10 s remains the stretch goal. Preserve
dependency-free Python and measure it periodically rather than diverting the
native campaign into Python accelerators.

Prefer shared rules for storage provenance, alias overlap, lifetimes, and
effects over additional syntax-specific exemptions. This supports the
intended proof/ownership design without requiring a wholesale rewrite now.

## Validation and limits

- The initial backend/ownership selection passed 65 tests, skipped 14
  cross-toolchain cases, and reproduced the imported strict-module failure.
  That failure passes with source attribution corrected.
- The two ownership regressions pass with hosted and native lowering,
  each using both direct x86-64 and C output. They also pass in a
  second-generation direct-built compiler, along with the power regression
  and the existing literal-field-view fixture.
- The focused follow-up selection passed 40 ownership/effect tests. The
  four positive review regressions passed hosted/native lowering and both
  output targets; copy-report and module-source tests also passed (8 pytest
  cases total in that selection). The second-generation compiler also
  passed narrowed-payload-layout, return-move, indexed-borrow, getter-field,
  and failure-effect fixtures, each with its explicit expected result.
- The review's two successive compiler builds took 20.81 s and 45.01 s.
  These are integration-run observations, not a new controlled performance
  baseline. µDewy was the existing native `udewy-la3`; this was not a fresh
  paired fixed-point certification.
- A final native compiler build also verifies the prefixed-quote fix and
  rejection of the shadowed intrinsic; the unsigned-refinement prototype
  still panics with its expected status 102. All five existing hosted
  prototype-mode tests pass.
- Review artifacts and logs are under
  `../dewy-build-artifacts/review-2026-09-20` relative to the repository.
  No release was published and the full corpus was not rerun here.

Remaining cautions are explicit: strict-copy report parity, complete scalar
lexing, the unresolved corpus expectation, and direct-build performance are
still work, not gates this review claims to have completed.
