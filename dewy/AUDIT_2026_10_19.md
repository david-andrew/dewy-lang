# Implementation and iteration audit

Requested by David; independent read-only reviews by **Claude Opus 5.5** and
**GPT-6.1 Sol**, starting at `bd9a3aca`. Both inspected the source, tests, build
tools, existing measurements, history and the Sloppy checkout. Neither ran
workloads or changed files. The primary agent checked their findings against
the implementation and prior negative evidence.

## Findings adopted

Both reviews identify the same process problem: repeated full certification
and large evidence reports for sub-percent changes consume too much of the
development cycle. Keep quick/focused checks per edit, and close coherent
batches with full tests, independent bootstrap and performance checks. Retrain
the optional optimized host at larger checkpoints. Favor a clear application
benefit or meaningful simplification over speculative micro-optimization.

The concrete corrections already implemented are:

- **CI test-list drift:** CI omitted the dedicated regex and recursive-value
  suites. It now imports `tools.core.TESTS`, retains two workers and one emitter,
  and has a ten-minute budget for bootstrap, tests and host preparation.
  Commit `a1c3969a`; the actual CI command's syntax and shared list were checked.
- **Overly coupled runtime certificates:** an inconclusive compilation result
  used to invalidate independently passing runtime evidence. Certificates now
  require complete reports and passing fixed-reference comparisons for the
  particular kernel's two modes, while retaining all identity, flags, harness,
  input and artifact checks. Unaccepted kernels fall back to timing; no whole
  stage is promoted. Commit `a1c94dc8`; 27 certificate tests pass.
- **Current work queue:** [COMPACT_STATUS](COMPACT_STATUS.md) separates existing
  capabilities, remaining boundaries and design questions from the historical
  restart log. The overview's obsolete claim that named callable arguments are
  unsupported has been corrected.

Both reviews prioritize the measured managed-call gap. Bounded wrapper
inlining now cuts default managed-helper runtime about 39% on the laptop,
without changing language rules.
The compiler itself should also remain a generated-program benchmark: the
native/GCC instruction gap is evidence of substantial backend opportunity,
not merely an excuse to keep optimizing the GCC build process.

A maintained instruction-measurement command and bounded differential fuzzing
are now implemented. Selective Sloppy ports include JSON token fast paths and
recursive-return optimization. Continue explicit triage of newer fixes and
libraries, reusing existing runners rather than building another framework.
Preserve representative application latency and distinct conformance-corpus
scaling alongside the synthetic throughput benchmark.

## Recommendations corrected or not adopted

- Sol initially suggested pooled/inline syntax children and reusable register
  scratch. On follow-up it inspected the preserved patches and withdrew both:
  those mechanisms were already tested and rejected. See
  [frontend storage](audits/2026-10-18/frontend-storage-experiments.json),
  [register workspace](audits/2026-10-19/register-workspace-pilot.json), and
  [direct projection](audits/2026-10-19/direct-projection-experiment.json).
  Revisit only with a materially different mechanism or workload and evidence
  of a substantial removable cost.
- Opus proposes a direct compact-AST frontend as a larger opportunity. This is
  a hypothesis, not a measured gain. The end-to-end Dewy-versus-Jo timing gap
  includes grammar and lexing differences; it cannot be attributed entirely
  to projection. Existing small projection/storage results do not justify a
  wholesale rewrite without better attribution.
- Instruction counts complement timing; they do not establish that cycles or
  latency improved. We are **not** adopting best-of-N timing, silently clearing
  the laptop regression observation, or replacing the existing performance
  criteria with an instruction-only rule.
- No relaxation of the 250k compilation or C/Rust-like runtime goals is adopted.
  Hardware, source counting, compiler-host configuration and workload shape must
  be explicit. The optional GCC host remains separate from native development;
  its result does not erase native code-quality work.
- Some review concerns cite pre-restart proof/trap policies. The current
  [GOALS](GOALS.md) already distinguish ordinary runtime checks from a later
  strict systems lane. Historical comments do not create new approval blockers.
  Any actual front-end or user-facing language change still requires David's
  approval, as requested in this audit.
- A missing `followup_ports` entry does not prove an upstream improvement is
  absent: several mechanisms were adapted independently for Dewy semantics.
  Inspect the code before declaring a port missing. Automatic wholesale merges
  of newer Sloppy surface semantics are not authorized.

## Evidence policy

Keep concise, reviewable summaries with source/binary identities and links to
reproducible evidence. Avoid duplicating entire manifests and raw reports in
each prose update. Preserve existing evidence and unfavorable observations;
compress raw checkpoint artifacts when appropriate rather than deleting them.
No new scheduler, background fuzzing service, or target relaxation was created
by this review. The next sequence is maintained in COMPACT_STATUS.

## Follow-up: generated stack traffic

Sol's follow-up audit identified private 32/40-byte record temporaries in hot
compiler functions that exceed the current scalar-promotion limit. Two bounded
mixed-field prototypes were implemented and tested. The second removes all
loads/stores in the targeted record-copy example, but raises whole-compiler
instruction counts by 1.3–4.5%; both were reverted before a full timing campaign.

A diagnostic emitter then mapped fresh accepted-compiler instruction samples to
frame storage, after proving its emitted machine-code section byte-identical.
Of 7,290 samples, 9.6% access spill slots, 7.6% save/restore callee-saved registers,
and 4.4% access medium record slots. These are attribution counts, not removable
performance budgets. Investigate actual lifetime and call-save decisions next.
[Prototypes, attribution and reproducible evidence](audits/2026-10-19/medium-record-sra.json).
