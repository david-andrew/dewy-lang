The Dewy programming language

Tools for the edit loop

Everything ships in one toolchain: the compiler, a watcher, a test runner, an interactive prompt and a language server.

Run, check and build

dewy hello.dewy                          # compile and run
dewy check hello.dewy                    # errors only
dewy check --obligations hello.dewy      # list sites that compile to runtime checks
dewy build hello.dewy --release -o hello
dewy build hello.dewy --target x86_64-windows -o hello.exe
dewy build hello.dewy --target wasm32 -o hello.html
dewy watch hello.dewy                    # rerun after each edit
dewy                                     # interactive prompt

With no file, dewy starts the interactive prompt at a terminal and runs a program piped to it otherwise. watch reruns a program after source changes and keeps a running game's state when it can. A wasm32 build writes an HTML page that runs the program in a browser. Cross-compiling needs only --target: the compiler writes executables itself. build --time reports how long each compiler phase took.

VS Code and the language server

Install the Dewy extension. It uses a bundled or installed compiler, or the one dewy.core.path names: a standalone bin/dewy-core or the checkout’s absolute tools/dewy path.

Through dewy lsp it provides diagnostics on unsaved files, completion, hover, go to definition, rename, signature help, semantic highlighting, inlay hints, quick fixes and Format Document, plus commands and code lenses to run tests and CodeLLDB debugging. See the extension guide.

Tests

dewy test project.dewy                   # every $test in the file
dewy test project.dewy bounce            # tests whose names contain "bounce"
dewy test --watch project.dewy           # rerun after edits
dewy test --json project.dewy            # one JSON object per test
dewy build project.dewy -g -o project-debug

A test is an ordinary function marked $test, and cases= runs it once per case:

add = (a:int b:int) => a+b

$test
adds_numbers = () => $expect add(20 22) =? 42

$test(cases=(1 2 -3))
adds_zero = (x:int) => $expect add(x 0) =? x, "{x} changed"

Each test runs in its own process on native hosts, so one that aborts does not stop the rest. A failed expectation shows the source line and the values compared. The language guide has the details.

Errors that explain themselves

let x:int32 = 2147483647
let y:int32 = x + 1

error: cannot prove exact integer result fits int32
    let y:int32 = x + 1
                  ^
    note: nothing bounds `x + 1` within int32 here
    help: widen the destination to `int` or state the domain as a refinement.
          For wrapping use `int32<overflow='wrap'>`. For saturation use
          `int32<overflow='saturate'>`

Diagnostics name the fact that is missing and suggest fixes; the editor offers many of them as quick fixes. Wording may change between versions; this site checks that the example is still rejected.
