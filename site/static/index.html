Dewy

An Everyday Language

Python-like ease. C-like speed. No hidden crashes.

Dewy reads like a scripting language and compiles to native code and WebAssembly. Before your program runs, the compiler proves that every index, division and narrowing conversion is safe, or tells you which fact is missing and how to supply it.

words.dewytested ✓
text = "the cat sat on the mat and the dog sat too"

let counts:dict<string int> = []
loop word in text.split(" ") {
    if word not in? counts counts[word] = 0
    counts[word] += 1      # proven present: no KeyError
}

loop [word n] in counts if n >? 1 printl"{word} × {n}"
printl"owls: {counts.get("owl") ?? 0}"

No hidden traps

An index, divisor or narrowing the compiler cannot prove safe is a compile error with a fix, not a crash in production.

300k+ lines/s

Single-threaded compile speed on each of the project’s flagship programs, library code included. No cache, no daemon.

Close to C

18 of 28 benchmark kernels run within 1.2× of the same algorithm in C at -O2. Closing the rest is on the roadmap.

Written in Dewy

The 200,000-line compiler builds itself. It makes programs for Linux (x86-64, ARM64), macOS (ARM64), Windows (x64) and the web, with no external linker.

What makes Dewy different

Every example on this page is compiled with the current compiler on each site build, with no runtime checks switched on, and its output is checked.

safety

Proven, or it doesn’t compile

In most languages xs[0] on an empty array is a crash, an exception or undefined behavior, discovered when it happens. In Dewy, indexing, division and narrowing conversions are proven from facts the compiler can see. When a fact is missing, the build stops and the error says which fact, what values would break it, and how to fix it.

first.dewytested ✓
first = (xs:array<int>) => {
    if xs.length =? 0 return none  # a value, not a crash
    xs[0]                          # proven: xs has an element
}
printl(first([3 1 4]))    # 3
printl(first([]))         # none

# A loop over the positions proves every index.
xs = [3 1 4 1 5]
total = 0
loop i in [0..xs.length) total += xs[i]
printl(total)             # 14
printl(xs.get(9) ?? -1)   # -1: no element 9
safety

The fix is ordinary code

A guard, a loop over the positions an array has, or get with a fallback: the facts come from code you would write anyway, not from annotations. A proven check costs nothing at run time. While prototyping, $runtime_checks turns unproven sites into checks that report the values they saw. Read how this compares in Safer than Rust.

units.dewytested ✓
from units import kg, m, N, J, W

# Units are values. Juxtaposition multiplies.
mass = 10kg
velocity = 30m/s
energy = 1/2 * mass * velocity^2   # 4500 J

force = 1000kg * 9.8(m/s^2)        # 9800 N
work = 20N * 10m                   # 200 J
power = work / 4s                  # 50 W

printl"{energy/J} J  {force/N} N  {power/W} W"
engineering & science

Physical units, built in

Dewy treats kilograms, meters, and seconds as values with dimensions, not as plain numbers. Juxtaposing a number with a unit multiplies them, dimensions carry through arithmetic, and mismatched dimensions are errors—so 20N * 10m is joules and 3m + 5s doesn’t compile. Dimensions are checked at compile time and cost nothing at runtime.

ranges.dewytested ✓
# Bounds are visible: [ ] includes, ( ) excludes.
window = [0..10)              # 0 1 ... 9
evens = 0,2..100              # step inferred from the pair
countdown = [10,8..0]         # negative steps too

printl(16 in? (5..15])        # false

# Slices use the same bounds.
samples = [3 1 4 1 5 9 2 6]
printl(samples[end-3..])      # [5 9 2 6]
printl('hello world'[0..5))   # hello
ranges

Ranges with clear bounds

Brackets say exactly which endpoints belong to a range, a second anchor sets the step—including negative steps—and the same bound forms drive loops, membership tests, and slicing.

loops.dewytested ✓
ratings = [
    'star wars' -> 73
    'star trek' -> 89
    'legend of the galactic heroes' -> 100
]

# One keyword covers while, for, and beyond.
loop [show rating] in ratings
    printl'I give {show} a {rating} out of 100'

# Iterators compose logically.
loop i in 0.. and letter in 'Dewy' printl'{i}: {letter}'
iteration

One loop to rule them all

There is no for / while / do-while zoo—loop takes any condition. The in operator assigns the next value and reports whether one existed, so iterators can combine with and or or in a single loop.

numbers.dewytested ✓
# Integers grow as needed instead of overflowing.
big = 2^100
printl(big)

# Dividing integers gives an exact fraction.
third = 1/3
printl(third + 1/6)       # 1/2

# Decimal literals are exact too.
printl(0.1 + 0.2 =? 0.3)  # true
numbers

Exact by default

int is the mathematical integer: word-sized while the value fits, big when it doesn’t, and never silently wrapped. Dividing integers gives a rational that prints as the fraction it is, and decimal literals are exact fractions unless a float is asked for. Floats are strict IEEE 754 when you want them.

refinements.dewytested ✓
# A type can carry a condition on its values.
Positive:type = int<(>? 0)>
NonEmpty:type = array<int length >? 0>

first = (xs:NonEmpty) => xs[0]     # no guard needed
span = (a:int b:int<(>=? a)>) => b - a
share = (total:int n:Positive) => total // n

printl(first([3 5 8]))    # 3
printl(span(3 10))        # 7
printl(share(84 2))       # 42

# first([]) and share(84 0) are compile errors.
type system

Types that carry facts

A refinement lets a type say “positive integer” or “non-empty array”. Inside the function the fact is known, so xs[0] needs no guard; at each call the compiler proves it from literals and control flow, and rejects a call that breaks it. Refinements cover integer ranges, relations between parameters, array and string lengths, and record fields.

primes.dewytested ✓
# `lazy` turns a loop into a generator:
# nothing runs until a value is pulled.
primes = ():>generator<int> => $outer lazy loop n in 2.. {
    loop d in 2..n {
        if d * d >? n { break }
        if n % d =? 0 { continue $outer }
    }
    n
}

# Take the first ten from an endless sequence.
let found = [loop _ in [0..10) and p in primes() p]
printl(found)
generators

Lazy sequences without ceremony

Put lazy in front of a loop or block and it becomes a generator that produces one value each time it is asked. Generators combine with other iterators in one loop header, and a pipeline consumed by a single loop fuses into that loop without allocating.

functions.dewytested ✓
# `&` combines implementations into one overload set.
format = ((value:int):>string => "integer: {value}")
       & ((value:string):>string => "text: {value}")

printl(format(42))      # integer: 42
printl(format("Dewy"))  # text: Dewy

# `@` passes a function without calling it.
double = (x:int) => x * 2
twice = (f:(int:>int) x:int) => f(f(x))
printl(twice(@double 10))   # 40
functions

Functions are ordinary values

Function literals are expressions like any other: pass them, store them, and combine them. The & operator merges two implementations into one overload set, and each call picks the one whose parameter type matches. @double names the function itself, ready to pass along.

objects.dewytested ✓
counter = (start=0) => [
    value = start
    increment = () => (value += 1)
]

# make a new counter object
count = counter(40)

# called on access
count.increment
count.increment

printl"count is {count.value}"
objects

Objects, blocks, and functions are one thing

Dewy’s syntax is deliberately unified: functions can construct structural objects, members can capture their siblings, and accessing a zero-argument function member calls it. Fields and behavior live together without separate class machinery, and a member that updates its siblings changes the object it is called on.
